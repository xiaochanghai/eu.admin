# Excel 导入管线统一与性能优化设计

## 目标

统一 `NPOIHelper.ImportExcel` 与 `ImportHelper.ImportData` 当前两套导入路径，使 `.xls`、`.xlsx` 在列映射、空行判断、Excel 行号、单元格取值和校验结果方面保持一致；随后通过逐批读取和逐批写库降低大文件导入的峰值内存。

校验发现业务错误时保留 `SmImportData`、`SmImportDataDetail` 和错误记录，调用方返回“导入完成但存在错误”，不将业务校验错误作为技术异常回滚。

## 当前问题

- `CommonServices` 先将工作表完整转换为 `DataTable`，再构造完整的明细实体列表，存在多份大对象同时驻留内存的问题。
- `FileAttachmentServices` 使用另一个直接读文件的 `ImportData` 重载，两条路径的空行、行号、字段范围和校验行为不一致。
- 直接读文件的重载分批写库但未执行与旧路径相同的 `Check` 校验。
- `ImportExcel` 对空表头、重复表头、缺失标题行和单元格读取异常缺少明确处理，并静默吞掉单元格异常。
- `SmImportDataDetail` 只能保存 `Col1` 至 `Col50`，当前读取过程没有统一执行 50 列边界校验。

## 方案

### 1. 统一 Excel 读取抽象

在 `NPOIHelper` 中增加批处理读取入口，输入文件路径、工作表名称、标题行索引和批大小，输出标题集合及带真实 Excel 行号的数据批次。

- `.xlsx` 使用 NPOI 的事件模型逐行解析，避免创建完整 `XSSFWorkbook`。
- `.xls` 使用 `HSSFWorkbook` 顺序读取。旧格式行数上限较低，但仍按相同批次接口向下游交付数据。
- 两种格式共用工作表选择、标题校验、空行判断和单元格文本规范。
- 标题行不存在、标题为空、标题重复、工作表不存在或有效列超过 50 时抛出明确的技术/配置异常。
- 公式单元格读取缓存计算结果；日期、布尔值和数字通过统一格式化逻辑输出，避免两种格式产生不同结果。
- 保留现有 `ImportExcel(...) -> DataTable` 作为兼容包装器，但正式导入流程不再调用它。包装器内部复用统一读取逻辑，避免两套规则继续分叉。

默认批大小为 1000 行，并集中定义为可调整常量。

### 2. 统一数据入库与校验

以 `ImportHelper.ImportData(Db, importDataId, template, filePath)` 作为文件导入的标准入口：

1. 校验参数、文件、模板详情和 50 列边界。
2. 创建一条 `SmImportData` 主记录。
3. 从统一读取入口接收批次，将每批转换为 `SmImportDataDetail` 后立即批量写库。
4. 所有批次成功后执行一次现有 `Check`。
5. 返回标题、导入行数和错误数，供调用方构建一致的响应消息。

接受 `DataTable` 的旧重载保留以兼容潜在外部调用，但改为把 `DataTable` 行送入同一个“批次转实体并落库”核心，不再维护独立的行号和校验实现。

业务校验错误不会抛异常。文件损坏、配置无效、数据库失败等技术异常仍抛出；若在批次写入过程中发生技术异常，清理本次 `importDataId` 已写入的主表、明细和错误数据，避免留下无法识别的半成品导入。

### 3. 调用点一致性

- `CommonServices` 改为直接调用标准文件导入入口，不再先构造完整 `DataTable`；列标题使用导入结果返回的标题集合。
- `FileAttachmentServices` 使用相同返回结果和校验语义。
- 两个入口均根据错误数返回“导入成功”或“导入完成，但存在 N 条错误”，不再一个入口抛错、另一个入口静默成功。
- 现有结果查询和转换接口保持不变，本次不改变前端响应结构。

## 内存与事务边界

- 内存中只保留当前约 1000 行的原始值和实体，不保留完整工作表、完整 `DataTable` 或完整实体列表。
- 不在整个文件解析期间持有长事务。每批写入独立完成；技术失败时执行按 `importDataId` 的补偿清理。
- `Check` 在数据全部写入后运行，以保持现有规则实现和跨数据库兼容性。
- 本次不并行使用同一个 `ISqlSugarClient` 写多个批次，避免连接和事务并发问题。

## 兼容性

- 同时支持 `.xls` 与 `.xlsx`。
- 保留现有公开 `ImportExcel` 方法和两个 `ImportData` 调用形态。
- 保持模板的 `SheetName`、`StartRow`、`ColumnNo`、Master/Detail 配置语义。
- `LineNo` 统一为真实 Excel 的 1 基行号，修正当前部分路径的偏移不一致。
- 不新增第三方 Excel 依赖。

## 测试与验收

- 用等价的 `.xls`、`.xlsx` 文件验证标题、日期、数字、布尔值、公式结果和空行行为一致。
- 验证指定/缺失工作表、缺失标题行、重复/空标题、超过 50 列时的错误信息。
- 用跨越批次边界的数据验证无丢行、无重复、真实行号正确。
- 验证文件路径导入和兼容 `DataTable` 导入生成相同的明细内容并执行相同校验。
- 验证业务校验错误保留数据与错误记录，并返回错误数而非抛出业务异常。
- 验证文件解析或批次写库发生技术异常时不会留下本次导入的半成品数据。
- 构建 `EU.Core.Common`、`EU.Core.Services`，运行新增定向测试与现有 NPOI 测试。

## 非目标

- 不重写现有 `Check` 规则体系。
- 不改变导入结果 DTO 和前端页面协议。
- 不在本次改造中分页化导入结果查询；若超大导入仍需要一次性返回全部结果，这部分响应内存应作为后续独立优化处理。
