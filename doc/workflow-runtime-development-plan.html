工作流运行态开发规格

范围仅包含流程申请、流程实例、节点推进、待办任务、审批记录、抄送和运行态查询。流程设计、PC/移动端表单布局与流程定义发布属于前置能力，不在本文实现范围内。

目标与边界

目标：用户提交流程申请后，系统基于已发布流程创建可追溯的实例和待办；审批人处理任务后，系统安全地计算下一节点、生成后续待办，并完整保留操作记录。
  • 一个业务申请单可关联一个流程实例；流程实例必须固定绑定启动时的已发布流程版本。
  • 申请单保存业务表单数据；流程实例保存审批状态、版本、当前节点和发起人，二者不能混为同一张表。
  • 运行态绝不读取或修改正在编辑的流程定义；只读取已发布版本快照。
  • 所有提交、审批、驳回、撤回和自动推进操作必须可审计、可幂等、可并发保护。

核心术语

对象含义示例状态

审批记录不可变的操作审计日志，记录谁在何时对哪个对象做了什么操作和意见。Submit、Approve、Reject、Withdraw、Transfer、Urge、AutoPass

数据模型

表职责关键字段
SmWorkFlowApplication流程申请单与业务表单、字段架构、显示值快照。BusinessId 是可选的外部业务主键；申请单自身主键始终是 Id。Id、ModuleId、BusinessId、ApplicationNo、Title、ApplicantId、FormDataJson、FormSchemaJson、FormDisplayJson、Status、SubmittedTime
SmWorkFlowInstance运行中的流程主记录。Id、ApplicationId、ModuleId、BusinessId、WorkFlowId、WorkFlowVersionId、StarterId、CurrentNodeId、Status、StartedTime、CompletedTime、RowVersion
SmWorkFlowInstanceNode实际经过的节点及节点配置快照。Id、InstanceId、DefinitionNodeId、NodeName、NodeType、NodeOrder、Status、EnteredTime、CompletedTime、SnapshotJson
SmWorkFlowTask个人待办任务；一个节点可按会签规则创建多条。Id、InstanceId、InstanceNodeId、AssigneeId、Status、TaskType、SourceTaskId、TransferredToTaskId、ReceivedTime、HandledTime、DueTime、RowVersion
SmWorkFlowActionLog不可修改的运行审计记录。Id、InstanceId、InstanceNodeId、TaskId、Action、OperatorId、Opinion、BeforeStatus、AfterStatus、CreatedTime、ExtraJson
SmWorkFlowCc抄送接收人与已读状态。Id、InstanceId、InstanceNodeId、RecipientId、ReadTime、CreatedTime
SmWorkFlowIdempotency提交、审批等写操作的请求去重与结果重放。Id、OperatorId、Action、RequestKey、RequestHash、ResponseJson、CreatedTime、ExpiresTime
SmWorkFlowOutbox事务内创建、事务后异步投递的通知事件。Id、EventType、AggregateId、PayloadJson、Status、RetryCount、NextRetryTime、CreatedTime、SentTime

申请单等可编辑记录可保留软删除字段；实例、实例节点、已处理任务、审批日志和 Outbox 属于运行历史，禁止物理或软删除。实例和任务表增加乐观并发字段 RowVersion。SmWorkFlowIdempotency 对 OperatorId、Action、RequestKey 建立唯一索引；SmWorkFlowInstance 对 ApplicationId 建立唯一索引；ApplicationNo 由服务端生成，并对 (TenantId, ApplicationNo) 建立唯一索引。BusinessId 非空时，同一 (TenantId, ModuleId, BusinessId) 最多允许一条草稿、审批中或异常申请；终态申请可按业务规则再次发起。

状态机

草稿→ 提交 →审批中→ 通过 →已通过 ；审批中→ 驳回 →已驳回 ；审批中→ 撤回 →已撤回 ；审批中→ 路由异常 →异常 ；异常→ 恢复 →审批中 ；异常→ 人工终止 →已作废
  • 草稿仅申请人可编辑或删除，不创建流程实例和待办。
  • 提交是 ActionLog 事件，不作为申请单持久状态；提交成功后申请单、实例同步进入审批中，申请表单快照不得再直接修改。
  • 终审通过、驳回、撤回和作废均为终态；终态实例不得再生成待办。
  • 撤回规则建议限定为“当前待办尚未处理且申请人本人操作”；撤回后取消所有未处理任务。
  • 条件无匹配、条件数据无法转换、审批人无法解析等运行错误进入 Exception；申请单同步标记为异常，取消后续自动推进，写入 RouteError 日志，并仅允许流程管理员重试路由、人工指定下一节点或终止实例。恢复成功后实例和申请单同步回到 Running/审批中；人工终止后同步进入 Cancelled/已作废，并写入 ResolveException 日志。

关键运行流程

1. 保存草稿与提交申请

  1. 校验模块已启用工作流、用户有发起权限、表单字段及必填项合法。
  2. 保存或更新 SmWorkFlowApplication；草稿可继续编辑。
  3. 提交时读取当前已发布流程版本；若不存在有效版本，拒绝提交。
  4. 在同一事务内锁定申请单，写入表单快照，创建实例、首个实例节点、首批待办和 Submit 日志。
  5. 在同一事务内写入待办通知的 SmWorkFlowOutbox 事件；事务提交后由后台任务异步投递。通知失败可重试，不得回滚已成功创建的任务。

2. 审批通过

  1. 按任务 Id 读取待办，校验任务为 Pending、审批人匹配当前登录用户、实例仍为 Running。
  2. 使用 RowVersion 或数据库行锁避免两个审批人重复处理同一任务。
  3. MVP 只支持单人审批：关闭当前任务，写入 Approve 日志并完成当前实例节点。后续支持或签时，首个同意任务完成节点并取消其余 Pending 任务；支持会签时必须配置通过阈值、驳回阈值和剩余任务关闭规则。
  4. 节点完成后，基于申请单 FormDataJson 计算条件分支，创建下一实例节点、待办和抄送。
  5. 若到达结束节点，将实例和申请单标记为已通过，并写入完成日志。

3. 驳回、撤回、转办与催办

  • 驳回：关闭当前节点未完成任务，实例进入已驳回；MVP 不支持退回指定节点。
  • 撤回：申请人仅能撤回仍在审批中的申请；取消所有 Pending 任务并写 Withdraw 日志。
  • 转办：保留原任务和处理链，原任务置为 Transferred 并写入 TransferredToTaskId；创建接收人的 Pending 新任务并写入 SourceTaskId。不可直接覆盖原任务的审批人。
  • 催办：不改变流程状态，仅写 Urge 日志并向当前 Pending 任务接收人发送通知；应限制频率。

条件与节点推进

  • 条件定义从实例绑定的已发布版本节点 ConditionsJson 读取，字段值从提交时冻结的 FormDataJson 读取；两者一律使用不可变 FieldCode/DataIndex，不得使用字段标题。
  • 提交时将所用字段编码、类型和显示标题写入 FormSchemaJson，将字典标签、人员姓名、部门名称和关联对象名称等提交时显示值写入 FormDisplayJson；字段定义或数据源后续变更不能影响历史申请单的展示、审计或条件解释。
  • 运行时只允许使用白名单运算符：eq、ne、gt、gte、lt、lte、in、isNull、notNull；严禁拼接 SQL。
  • 必须定义无条件兜底分支；无匹配分支时将实例置为 Exception、写入 RouteError 日志并停止推进，不得静默跳过或保留为 Running。
  • 审批人规则在节点激活时解析为具体用户并写入任务；不要在待办查询时动态重新计算组织关系。
  • 自动通过、无审批人、重复审批人、审批人离职等异常场景必须有明确策略和 ActionLog。
  • MVP 仅支持一条活动节点路径，不支持并行网关。此阶段 CurrentNodeId 可作为当前节点缓存；后续支持并行时，以 SmWorkFlowInstanceNode.Status = Active 作为活动节点事实来源。

接口清单

接口用途权限与约束
POST /api/SmWorkFlowApplication保存申请草稿。申请人；仅草稿可更新。
POST /api/SmWorkFlowApplication/{id}/submit提交并创建流程实例。申请人；支持幂等键，重复提交不得创建多个实例。
GET /api/SmWorkFlowApplication/{id}获取申请单、表单快照与流程摘要。申请人、当前/历史审批人、抄送人或管理员。
GET /api/SmWorkFlowTask/my查询我的待办。当前用户；支持模块、状态、日期、关键字分页筛选。
GET /api/SmWorkFlowTask/my-handled查询我的已办。当前用户；按操作日志或已处理任务分页。
POST /api/SmWorkFlowTask/{id}/approve同意当前待办。当前任务审批人；携带意见、并发版本与幂等键。
POST /api/SmWorkFlowTask/{id}/reject驳回当前待办。当前任务审批人；意见必填。
POST /api/SmWorkFlowApplication/{id}/withdraw撤回申请。申请人；只允许审批中且尚未完成的实例。
POST /api/SmWorkFlowTask/{id}/transfer转办任务。当前审批人或管理员；保留任务链和理由。
POST /api/SmWorkFlowTask/{id}/urge催办。申请人或流程管理员；限频。
POST /api/SmWorkFlowInstance/{id}/resolve-exception重试路由、人工指定下一节点或终止异常实例。流程管理员；实例必须为 Exception，携带 RowVersion 与 Idempotency-Key；事务内锁定实例，必须填写处理原因并写入 ActionLog。
GET /api/SmWorkFlowInstance/{id}获取流程图、节点状态、任务和操作记录。按实例可见性鉴权。
GET /api/SmWorkFlowCc/my查询抄送给我的流程。当前用户。

页面主要能力

权限、可靠性与审计

  • 后端必须基于当前登录用户鉴权，前端隐藏按钮不能作为权限边界。
  • 任务处理接口要求任务状态为 Pending、任务审批人为当前用户，并校验 RowVersion。
  • 提交、审批和异常处理接口支持客户端 Idempotency-Key；服务端在 SmWorkFlowIdempotency 中按用户、动作和键去重，并对重复成功请求返回首次处理结果。
  • BusinessId 非空时，数据库使用过滤唯一索引 (TenantId, ModuleId, BusinessId) WHERE BusinessId IS NOT NULL AND Status IN ('Draft', 'Approving', 'Exception') 限制一条活动申请；不以应用层查询代替该并发约束。
  • 所有状态变更在一个数据库事务内完成：实例、节点、任务、申请单状态与 ActionLog 必须一致。
  • 业务事务内写入 Outbox/消息表，事务提交后异步发送通知；失败可重试并记录发送状态。
  • ActionLog 仅新增不修改、不删除；记录操作人、来源、时间、意见、前后状态和必要的上下文。
  • 申请单和流程详情的字段脱敏、附件访问和数据权限需复用业务模块现有权限模型。
  • MVP 不启用 DueTime 到 Expired 的自动转换；启用 SLA 后再实现定时扫描、超时通知、自动转办或终止策略，并为每项策略写入 ActionLog。

MVP 实施顺序

  1. 前置完成 SmWorkFlowVersion、发布快照和版本节点关联；运行态只能启动已发布版本，禁止引用编辑中的流程定义。
  2. 建立申请单、实例、实例节点、任务、操作日志、幂等记录和 Outbox 表及索引、枚举和迁移脚本。
  3. 实现申请草稿、提交、已发布版本读取、首节点任务创建、幂等处理和我的待办查询。
  4. 实现同意、驳回、节点推进、条件计算、异常实例处理、结束节点处理与实例详情。
  5. 实现我发起的、我的已办、撤回和审批轨迹页面。
  6. 补充乐观并发、幂等、权限校验、事务测试和异常分支测试。
  7. 最后实现抄送、通知、催办、转办、会签/或签、时限和超时处理。
MVP 先支持单人审批、条件分支、同意、驳回、撤回和待办。会签、顺序审批、退回指定节点、委托、加签、SLA 和自动催办应在核心链路稳定后逐步引入。
