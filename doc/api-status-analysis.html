二、各状态的实际语义

1. Status = 200

ServiceResult<T>、ServiceResult 和 ServicePageResult<T> 的 Status 默认值均为 200。

public int Status { get; set; } = 200;

正常成功响应通常为：

{
  "Status": 200,
  "Success": true
}
注意：Status = 200 不保证业务成功。 ServiceResult<T>.OprateFailed(message, data) 会保留默认状态 200，同时设置 Success = false。

2. Status = 201

泛型方法 ServiceResult<T>.OprateFailed(string message) 明确将状态设置为 201，表示普通业务失败。

{
  "Status": 201,
  "Success": false,
  "Message": "具体业务错误信息"
}

项目中的典型场景包括用户账号或密码错误、用户不存在、导入失败、模块编码错误和 Redis 操作失败等。

该值是项目自定义语义，并不是标准 HTTP 201 “Created”的含义。

3. Status = 401

表示请求没有通过身份认证，例如：

  • 未携带有效身份凭证；
  • Token 或会话失效；
  • 用户不存在、已删除或被禁用。

认证处理器会同步把 HTTP 响应状态设置为 401。

4. Status = 403

表示用户身份已经确认，但访问权限等级不足。默认消息为：

很抱歉，您的访问权限等级不够，联系管理员!

授权处理器会同步把 HTTP 响应状态设置为 403。

5. Status = 404

ApiResponse 中已定义资源不存在状态，默认消息为 资源不存在!。但当前仓库没有找到 StatusCode.CODE404 的实际调用。

因此该值目前属于预留状态；普通不存在的路由可能由 ASP.NET Core 直接返回 HTTP 404，并不一定带统一响应结构。

6. Status = 500

该值主要来自以下场景：

  • 未处理的系统异常；
  • 非泛型 ServiceResult.OprateFailed(...)；
  • Controller 或 Service 基类中的 Failed(...)；
  • 模型绑定或参数验证错误经过全局过滤器转换后返回。

四、HTTP 状态与响应体 Status 的区别

响应 JSON 中的 Status 是普通业务字段，不会自动决定 HTTP 状态码。

  • 401、403 的认证/授权处理器会明确设置对应 HTTP 状态。
  • 全局异常过滤器设置响应体 Status = 500，但其 ContentResult 未明确设置 HTTP 状态，实际 HTTP 状态可能仍为 200。
  • 参数错误被转换为普通 JsonResult 后，响应体可能是 500，但 HTTP 状态可能是 200。

五、Data.Status 与外层 Status

示例响应中实际存在两个同名字段：

{
  "Status": 200,
  "Data": {
    "SessionId": "00000000-0000-4000-8000-000000000001",
    "Status": "ALREADY_STORED"
  }
}
  • 外层 Status: 200：统一响应包装状态。
  • 内层 Data.Status: "ALREADY_STORED"：具体接口的业务流程状态。

当前仓库中没有检索到 ALREADY_STORED、投递会话已存在 或示例中的固定 SessionId，因此无法从当前代码整理出该业务接口全部的字符串状态。 这部分可能来自其他服务、不同分支、尚未同步的代码或运行时依赖。
