为什么不做自由画布

自由拖拽会带来移动端适配、遮挡、性能和配置错误问题。管理类 App 更适合稳定模板。

第一版边界

先支持列表页，包含搜索、筛选、统计、列表、空状态、点击跳转。详情页和表单页后续扩展。

RN 安全策略

RN 端只渲染白名单组件，不执行动态脚本。配置错误时降级为空状态或默认模板。

Runtime Architecture

运行时架构

后台配置页面结构，API 输出 JSON，RN 拉取配置并按组件白名单渲染。数据仍走现有接口或自定义 API。

配置器拖拽组件、绑定字段、设置状态颜色
配置存储保存 PageConfig JSON 和版本号
配置接口RN 按 PageCode 读取页面配置
数据接口QueryByFilter 或自定义 API 获取数据
RN 渲染按模板渲染列表和操作

Reference Editor

现有 React DnD 编辑器可复用点

参考项目 E:\Source\react-antd-low-code\src\components\editor 已经具备低代码编辑器的基础骨架：左侧组件库、中间画布、右侧属性面板、组件树状态、schema 驱动预览和保存 JSON。这套结构适合迁移为移动端列表配置器，但组件模型需要从 HTML/Antd 改成 RN 白名单组件。

可以直接借鉴

  • index.tsx：三栏式编辑器布局，使用 DndProvider + HTML5Backend 管理拖拽上下文。
  • Left/DragItem.tsx：左侧组件通过 useDrag 输出组件节点数据。
  • Canvas/index.tsx：画布用 useDrop 接收新组件或已有组件移动。
  • Canvas/Item.tsx：每个节点同时支持 drag/drop，通过鼠标位置判断插入到上方或下方，并递归渲染 children。
  • Right/index.tsx：根据当前选中节点读取 schema/edit，动态渲染属性表单。
  • codeTreeSlice.ts：用组件树保存页面结构，包含 append、move、focus、remove、update props 等基础操作。

需要改造

  • 不要继续使用 HTML/Antd 组件作为最终 schema，改成移动端白名单组件。
  • 不要允许任意 HTML 嵌套，列表页只允许纵向组件编排和受控 item 插槽。
  • 把 Grid/Form/div/Input 这类 Web 组件替换为 SearchBar/Tabs/StatRow/List/EmptyState/FloatingAction。
  • 列表 item 内部采用模板化插槽拖拽，例如 image、title、subtitle、description、statusTag、metrics、actions。
  • 保存结果不生成 React 代码，而是生成 RN 运行时可消费的页面 DSL JSON。

Component White List

组件体系：页面组件 + Item 字段组件

方案默认直接使用 Item 自定义，不再把列表 item 固定为几种模板。页面层负责搜索、筛选、统计、列表等结构；Item 层负责单条卡片内部字段拖拽、字段绑定和显示规则。

页面组件

  • searchBar：搜索框，绑定一个或多个查询字段。
  • tabs：顶部筛选，绑定状态、类型等枚举字段。
  • statRow：统计条，用于总数、异常数、待处理数。
  • list：主列表，支持分页、下拉刷新、上拉加载。
  • emptyState：空状态，支持文案和图标。
  • floatingAction：右下角操作按钮，支持权限控制。

Item 字段组件

  • row、column：受控布局容器，用于组织字段块。
  • text、iconText：绑定文本字段，支持前缀、后缀、空值和最大行数。
  • image：绑定图片或文件字段，支持预设尺寸和圆角。
  • statusTag：绑定状态字段，通过状态映射显示文案、颜色和图标。
  • metric：绑定数字、版本、金额等指标字段。
  • divider、spacer、actionButton：用于分隔、留白和受控操作。

Flexible Item Layout

列表 Item 自定义字段绑定

Item 不再只使用固定字段模板，而是升级为“受控自由布局”：外层仍由卡片模板保证移动端稳定，内部允许拖拽字段块、绑定数据字段、配置格式化和显示样式。

可拖拽字段组件

  • TextField：文本字段，支持前缀、后缀、空值、最大行数和格式化。
  • ImageField：图片字段，支持固定尺寸、圆角和占位图标。
  • StatusTag：状态标签，按状态映射显示颜色、文案和图标。
  • Metric：指标字段，适合健康度、次数、金额、版本号等。
  • IconText：图标 + 文本，适合位置、时间、负责人等信息。
  • Divider、Spacer：控制分隔和间距。
  • Row、Column：受控容器，用于横向和纵向排列字段。
  • ActionButton：操作按钮，支持跳转、复制、拨号等受控动作。

必要限制

  • Row / Column 最多嵌套 2 层，防止配置复杂后移动端布局失控。
  • 图片尺寸只能从预设中选择，例如 40、48、56、64。
  • 文本默认最多 1 到 3 行，超出省略，避免撑破卡片。
  • ActionButton 每个 item 最多 2 个，避免列表操作过载。
  • 只允许使用样式 token，不开放任意 CSS 或动态代码。
  • RN 端只渲染白名单节点，配置错误时降级为空值或默认样式。

Page Types

移动端列表页与表单页

移动端低代码建议明确分成两类页面：ListPage 和 FormPage。两者共用数据源、动作系统、字段格式化、权限和主题，但使用不同的渲染器。

ListPage

  • 负责查询、筛选、展示、分页、下拉刷新和点击跳转。
  • 页面结构通常由 SearchBar、Tabs、StatRow、List、FloatingAction 组成。
  • List 内部默认使用 customCard，通过 itemLayout 自定义字段布局。
  • 适合设备列表、更新记录、工单列表、客户列表、配置列表。

FormPage

  • 负责新增、编辑、详情回显、校验、提交和提交后动作。
  • 表单结构由 Section 和 Field 组成，支持拖拽分组和字段排序。
  • 字段支持显隐条件、只读条件、默认值、校验规则和联动。
  • 适合设备新增、工单处理、配置编辑、用户资料维护。

RN 渲染器拆分

RN 端根据 pageType 分发到不同渲染器。共用数据源解析、动作执行、条件判断、字段格式化、主题和权限能力。

主渲染器

  • DynamicListPageRenderer：渲染列表页。
  • DynamicFormPageRenderer：渲染表单页。

共用能力

  • DataSourceResolver：统一解析 module/api/detail/submit 数据源。
  • ActionExecutor：执行 navigate、submit、backAndRefresh、copy、call 等动作。
  • ConditionEvaluator：处理显隐、只读、必填和联动条件。
  • FieldFormatter：处理日期、数字、金额、枚举和空值显示。
  • PermissionGuard：按用户权限控制组件和动作显示。
