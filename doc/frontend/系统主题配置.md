# 系统主题配置

系统配置页的源码入口为 [config/index.tsx](../../eu.admin.react/src/views/system/setup/config/index.tsx)。主题面板位于同目录，配置转换逻辑共用于维护与运行时，统一从 [src/config/theme.ts](../../eu.admin.react/src/config/theme.ts) 直接导入。

如需通过动态菜单打开系统配置页，将菜单的组件路径（`element`）配置为 `/system/setup/config/index`。菜单的访问地址由其 `path` 单独决定。

本页通过 `GET /api/SmConfig/GetListByGroup` 展示分组，默认选择接口返回的第一项。`Type=system-theme` 的分组展示主题编辑面板。

主题配置按选项保存到该分组的 `SmConfig` 明细中，`ConfigCode` 为 `theme.<字段名>`，例如 `theme.layout`、`theme.primary`、`theme.allowCustom`。每项独立存储，以符合 `ConfigValue` 最长 32 字符的服务端限制。

- 布尔值保存为 `Y`/`N`，读取时兼容 `true`/`false` 和 `1`/`0`。
- 布局支持 `vertical`、`classic`、`transverse`、`columns`；颜色为六位十六进制色值；圆角为 1–20 的整数。
- 主题颜色复用右上角皮肤设置的色盘、HEX 输入和预设色块；本页选择颜色仅修改待保存草稿。
- 缺失或非法的值使用面板默认值。第一次保存会新增缺失项；后续只更新变化项。
- 保存前重新查询当前分组，已有记录通过 `PUT /api/SmConfig/{ID}` 更新，缺失记录通过 `POST /api/SmConfig` 新增。部分成功时保留成功记录的 ID，失败项保留草稿以便重试。
- 保存期间禁止重复保存、刷新和修改主题。组件卸载后停止发送后续主题写入请求；已经发出的请求可能已被服务端保存。
- “允许用户自定义主题”开启时，下面的布局、颜色和其他主题控件全部禁用，原有值保留；总开关和保存按钮仍可操作，关闭总开关即可编辑系统统一主题。

登录或刷新页面初始化时读取一次系统主题，复用现有 Redux persist 缓存，不增加个人主题备份或缓存转换：

- 允许自定义：不覆盖主题字段，沿用本地缓存，并显示主题抽屉入口。
- 禁止自定义：将后台主题字段直接写入现有 global 状态，由 Redux persist 写入缓存，关闭并隐藏主题抽屉。
- 再次允许自定义时，以当前缓存为起点；被系统主题覆盖的旧个人偏好不会恢复。缓存仍沿用项目原有的浏览器共享方式。
- 加载期间隐藏主题入口，保留当前缓存外观；请求失败沿用统一拦截器的错误提示及跳转，不再额外弹出主题加载失败提示，也不自动重试。请求成功但主题响应格式无效时，由 Hook 提示配置格式错误。认证失效仍走原有登录失效流程。
- 注销或卸载时取消请求，忽略过期登录会话的响应。
- 参数维护保存后刷新页面生效，不增加保存事件同步或后台轮询。
- 对话布局切换、菜单折叠等操作沿用原实现，不对普通 Redux 更新增加统一拦截。

运行时调用只读接口 `GET /api/SmConfig/GetClientConfig`，返回 `ServiceResult<ClientConfigDto>`。主题位于 `Data.Theme`，字典键为 `layout`、`primary`、`allowCustom` 等短键，值为字符串。Hook 校验 Theme 为对象后，补回 `theme.` 前缀交给现有主题解析器，将 Y/N 转为布尔值、borderRadius 转为数字；空字典使用默认值，缺失或无效的 Theme 按加载失败处理。配置维护页面仍使用带 `theme.*` 编码的分组明细。新接口沿用 `SmConfigController` 的认证与过滤器，仅返回主题字段白名单。普通参数读写接口及其权限不变，无表结构变化或启动时写库。

运行时选择有效、未删除的 `Type=system-theme` 分组，按 `Sequence`、`ID` 排序取第一组。无分组返回空字典，使用默认配置（允许个人主题）；同组重复参数代码视为读取失败并降级，缺失或非法参数值按现有解析默认值处理。配置沿用现有表的系统共享范围，没有增加租户私有主题。

先发布后端只读接口再发布前端。旧后端缺少接口时前端会降级，不影响业务访问。回滚前端即可恢复原主题设置入口，后端只读接口可保留；已经覆盖的本地个人主题不会自动还原。新增方法位于生成标记的 Controller、IService、Service 中，后续重新生成时需保留这些手写扩展。

验证时检查：首次保存空分组、修改后刷新回显、部分失败重试、重复点击保存、空分组列表和非法配置值。现有 API 按条保存，无整组事务和并发版本检查。
