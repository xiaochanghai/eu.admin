# 路由初始化

刷新时权限菜单需重新加载（auth 不参与 Redux 持久化）。菜单尚未返回时，静态通配路由显示 Loading；菜单就绪后，同一次渲染注册动态路由并启用 404，避免首屏误显示 404。

组合路由时不得修改 `wrappedStaticRouter` 中的共享对象，否则组件重新挂载时会复用被污染的 404。通配路由必须保留 RouterGuard。

每次创建 router 实例时必须分配新的 Provider key，并在实例被替换或卸载时调用 dispose 清理监听。React Router Provider 的内部 state 不会因 router 属性变化而立即重置；复用 Provider 会把旧的通配路由匹配结果与新路由表结合，短暂显示 404。

登录页在权限菜单返回后仍保留静态路由，离开 `/login` 时再切换完整路由，避免登录流程中途重挂载。通过 router 订阅同步 pathname，兼容 hash 和 history 模式。无 token 时不启用动态路由。

每次 `setToken` 都同步清空菜单、扁平菜单、可见菜单和按钮权限，并递增 `auth.sessionVersion`。重新登录写入 token 时没有旧菜单可供守卫放行，必须等待本次权限加载成功。

权限初始化复用同一会话版本的进行中请求。按钮与菜单均加载成功、菜单非空且 token 与会话版本仍匹配时才写入权限；即使重新登录拿到相同 token，旧会话的返回结果也不能写入，Hook 中的异常处理不清空新会话的 token。路由入口接收初始化失败，权限 Hook 清理当前 token 后由守卫跳转登录。守卫监听 token、菜单及路径变化，登录成功跳转使用 replace。

在 `eu.admin.react` 运行 `node --test scripts/test-permission-session.mjs` 可验证权限清空、同会话请求去重、相同 token 的旧会话结果隔离及旧请求失败。该测试使用真实 reducer 和隔离 API，不连接后端。

回归检查：登录后刷新业务 URL、菜单接口慢响应、组件重新挂载、菜单加载完成后访问不存在的 URL，以及未登录直接访问业务 URL。预期分别为加载后显示业务页、加载提示、正常恢复、404、跳转登录。

另需检查：正常登录及退出、权限请求重复触发、菜单请求失败或空菜单、请求过程中退出或切换账号。失败应回到登录，旧会话结果不得覆盖新会话权限。

## 标签页切换动画

保留 `keepalive-for-react` 的缓存与刷新机制。`LayoutMain` 为缓存节点设置 `page-cache` 类，通过容器的 `page-animation-*` 类选择动画，切回已缓存页面同样生效。关闭库的延迟切换选项 `transition`，使用 CSS 入场动画，避免等待离场阶段。不随系统减少动态效果设置自动关闭，也不修改操作系统设置；用户可在主题配置中明确选择“关闭”。

参考 skyroc 的参数提供六种模式：淡入、滑动淡入、垂直淡入、缩小淡入、放大淡入、缩放进入。默认 `fade-slide` 从左侧 30px 淡入，时长 0.3 秒。主题抽屉及系统主题配置均提供“页面切换动画”选择，沿用允许用户自定义主题的控制。配置键为 `theme.pageAnimation`，前端状态为 `global.pageAnimation`；旧配置缺失或值无效时回退为 `fade-slide`。未新增依赖、修改路由或替换缓存实现。

在 `eu.admin.react` 运行 `node --test scripts/test-page-animation.mjs`，验证旧配置回退、七种选项的配置往返及 LESS 编译。本次代码变更不自动写入数据库，系统主题配置需通过现有保存操作生效。

回归检查：首次打开页面、A/B 标签来回切换、快速连续切换、缓存表单内容保留、标签刷新，以及系统关闭动画时仍有页面切换动效。
