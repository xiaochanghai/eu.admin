# SmModule 表单控件类型

> 状态：CURRENT  
> 前端选择器事实源：[`CompDatas.tsx`](../../../eu.admin.react/src/views/system/config/form/components/CompDatas.tsx)  
> 运行时渲染事实源：[`Elements/Index.tsx`](../../../eu.admin.react/src/components/Elements/Index.tsx)  
> 最后核对：2026-08-07

`SmModuleColumn.FieldType` 必须使用本文件列出的精确值，大小写敏感。生成模块 SQL 时先读取上述源码；源码变化时同步更新本文，不能依赖历史记忆或数据库中曾出现过的值。

## 1. 当前可用控件

| `FieldType` | 维护页面名称 | 常见用途 |
|---|---|---|
| `Input` | 单行文字 | 普通字符串、编号、名称、联系方式 |
| `TextArea` | 多行文字 | 备注、描述、多行内容 |
| `InputNumber` | 数字输入框 | 数量、金额、比率和有上下限的数值 |
| `InputPassword` | 密码输入框 | 需要遮蔽显示的输入；不得据此假定服务端已加密 |
| `ComboBox` | 下拉选择（字典） | LOV/字典型固定选项 |
| `ComboGrid` | 下拉选择（接口） | 通过公共列表或接口选择关联记录 |
| `Switch` | 开关 | 布尔状态，例如 `IsActive` |
| `DatePicker` | 日期选择器 | 单个日期 |
| `DateRangePicker` | 日期段选择器 | 日期区间 |
| `WeekRangePicker` | 周段选择器 | 周区间 |
| `MonthRangePicker` | 月段选择器 | 月区间 |
| `QuarterRangePicker` | 季度段选择器 | 季度区间 |
| `DateTimePicker` | 日期时间选择器 | 单个日期时间 |
| `DateTimeRangePicker` | 日期时间段选择器 | 日期时间区间 |
| `TimePicker` | 时间选择器 | 单个时间 |
| `TimeRangePicker` | 时间段选择器 | 时间区间 |
| `Radio` | 单选框 | 少量互斥选项 |
| `Checkbox` | 多选框 | 多个可组合选项 |
| `ColorPicker` | 颜色选择器 | 颜色值 |
| `ImageCover` | 封面上传 | 封面图片 |
| `FileUpload` | 文件上传 | 附件上传 |

## 2. 生成与维护规则

- `FieldType` 与列表展示使用的 `ValueType` 是不同维度：前者决定表单组件，后者决定列表格式。不得用 `dateTime` 充当 `FieldType`，也不得用 `DateTimePicker` 充当 `ValueType`。
- 表单排序字段统一使用后端实体名称 `FromTaxisNo`；不得再生成或使用错误名称 `FormTaxisNo`。列表排序继续使用 `TaxisNo`，两者均以 100 为常用递增间隔。
- 新增脚本只能从 `FormComponents` 当前未注释的项目中选择 `fieldType`；`CompDatas.tsx` 中整段注释的候选组件不属于已启用能力。
- 生成或修改 `FieldType` 后，还必须确认其存在于 `SUPPORTED_FIELD_TYPES`/`FIELD_MAP`。若只存在于选择器但不能被 `FieldLayout` 渲染，应先修复前端能力，不能生成会显示“不支持的字段类型”的配置。
- 没有明确编辑需求的展示字段可以保持 `FieldType=NULL` 并设置 `HideInForm=true`；需要进入表单的业务字段必须选择明确且受支持的类型。
- `ComboBox` 应配置有效字典/LOV 数据源；`ComboGrid` 应配置有效公共列表或接口数据源。名称显示字段与 ID 提交字段应成对设计，不能让显示名称覆盖关联 ID。
- `Radio`、`Checkbox` 需要选项数据源；`FileUpload` 应结合 `Accept`、`MaxFileSize` 和后端上传限制；`InputNumber` 应按业务需要配置 `Minimum`、`Maximum`。
- 日期、时间、范围类型必须与实体字段、请求 DTO、序列化格式和 `ValueType` 对齐；范围控件通常不是单一标量字段，生成前必须确认实际提交契约。
- `InputPassword` 只改变浏览器显示方式，不等于加密、脱敏或安全存储；密码和密钥字段仍必须遵守后端安全边界。

## 3. 相关属性依赖

维护页面的属性显示规则由 [`fieldSettingSchema.tsx`](../../../eu.admin.react/src/views/system/config/form/components/fieldSettingSchema.tsx) 定义。生成脚本时至少检查：

| 控件 | 重点属性 |
|---|---|
| `Input` | `DefaultValue`、`Validator`、`ValidPattern`、`IsUnique`、长度、`Placeholder`、`IsAutoCode` |
| `TextArea` | `DefaultValue`、校验、长度、`Placeholder`、`MinRows`；`MinRows=NULL` 时运行时默认 3，设置时必须大于 0 |
| `InputNumber` | `DefaultValue`、`Minimum`、`Maximum`、`Placeholder` |
| `ComboBox` | 字典/LOV 数据源、`IsMultiple`、`MultipleMaxCount` |
| `ComboGrid` | 公共列表/接口数据源、`IsMultiple`、`MultipleMaxCount`、关联 ID/名称字段 |
| `Radio`、`Checkbox` | `DataSource` |
| 日期和时间类 | `AllowClear`、实体/DTO 类型和序列化格式 |
| `FileUpload` | `Accept`、`MaxFileSize`、上传权限和服务端限制 |

属性依赖只表示维护 UI 是否展示配置项，不自动证明组合在业务接口中有效。最终仍以组件实现、实体/DTO、接口和实际交互验证为准。

列表字段的 `Align` 只允许 `left`、`center`、`right` 或空值；空值由后端输出为默认 `center`。生成脚本和维护页面不得写入数字或其他 CSS 对齐值。
