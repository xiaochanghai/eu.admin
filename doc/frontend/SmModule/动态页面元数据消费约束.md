# 动态页面元数据消费约束

> 状态：`CURRENT`
>
> 最后核对：2026-08-10

本文件适用于前端对 `SmModules`、`SmModuleSql`、`SmModuleColumn` 页面模块元数据的消费。后端聚合关系和维护规则见 [`后端 SmModule 索引`](../../backend/SmModule/README.md)。

## 1. 前端事实源

- API 入口：[`src/api/modules/module.ts`](../../../eu.admin.react/src/api/modules/module.ts)。
- 契约类型：[`src/api/interface/index.ts`](../../../eu.admin.react/src/api/interface/index.ts) 中的 `ModuleInfo`。
- 客户端缓存：[`src/redux/modules/module.ts`](../../../eu.admin.react/src/redux/modules/module.ts)，按 `moduleCode` 保存模块信息和页面状态。
- 通用消费者：`src/components/ProTable/**`、`src/components/Elements/**`、`src/components/ProTableEditable/**`。
- 模块维护入口：[`src/views/system/privilege/module/index.tsx`](../../../eu.admin.react/src/views/system/privilege/module/index.tsx)，包含模块基本信息、SQL 配置及表单/栏位配置入口。
- 表单控件选择器：[`CompDatas.tsx`](../../../eu.admin.react/src/views/system/config/form/components/CompDatas.tsx)；精确的 `FieldType` 取值和生成规则见 [`表单控件类型.md`](表单控件类型.md)。

## 2. 固定边界

- 页面以稳定的 `moduleCode` 调用 `GET /api/SmModule/GetModuleInfo/{moduleCode}`，不得在普通业务页面分别请求三张配置表后自行组装另一套模块协议。
- `columns` 用于列表/查询展示，`formColumns` 用于表单渲染；二者可以来源于同一栏位但具有不同模式和排序，不得假定数组完全相同。
- 列表页面 Column 顺序使用 `TaxisNo`，表单页面控件顺序使用 `FormTaxisNo`；前后端字段名必须完全一致。`ColumnMode` 仅使用小写 `list`、`form` 或空值。
- SQL 配置属于服务端查询边界。普通页面不得接收、拼接或执行 `SmModuleSql` 原始 SQL；SQL 查看/维护能力只能留在受权限保护的系统模块维护入口。
- `ModuleInfo` 字段名称和大小写必须与真实响应一致。修改 `moduleId`、`moduleCode`、`columns`、`formColumns`、`url`、按钮权限或主从字段时必须同步后端契约。
- `optionPosition` 只接受 `left`/`right`，通用列表据此固定 `option` 操作列；缺失或非法值回退到 `left`。`isAllowCustomColumn=false` 时隐藏列设置入口，缺失时按允许处理以兼容旧响应。
- Redux 中的模块信息按 `moduleCode` 缓存。账号/租户切换、权限变化或维护配置保存后，不得继续使用旧模块元数据；必须清理或重新拉取对应缓存。
- 业务页面可以用 `moduleCode` 选择模块，但不得复制通用表格、动态表单、权限和查询组装逻辑来绕过统一组件。
- 新增或生成 `SmModuleColumn.FieldType` 时必须使用 `CompDatas.tsx` 当前启用的精确 `fieldType`，并确认 `Elements/Index.tsx` 中存在对应运行时映射；注释中的候选组件不得当作已支持控件。

## 3. 修改与验证

- 新增动态页面时必须确认后端三表配置完整，并验证加载、空配置、错误配置、无权限和刷新恢复。
- 新增或修改栏位类型时，同时检查列表渲染、搜索、表单提交、校验、导入导出、合计、跳转和工作流条件。
- 修改 `TextArea.MinRows` 或列表 `Align` 时验证保存后重新加载仍保持配置；`MinRows` 必须大于 0，`Align` 仅允许 `left`、`center`、`right` 或空值。
- 模块维护保存成功后应重新获取对应 `ModuleInfo`；不能只刷新维护列表而让业务页面继续使用旧 Redux 数据。
- 跨端字段或行为变化附加 `API-CONTRACT` 和 `CROSS-END-CONTRACT`，最低运行 `pnpm type:check` 与对应后端编译/测试。
- 当前没有自动化前端测试脚本，必须准确记录手工/针对性验证范围，不得声称动态页面全量回归通过。
