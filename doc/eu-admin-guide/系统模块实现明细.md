# EU-Admin 系统模块实现明细

> 状态：`CURRENT`
>
> 用途：记录系统管理、平台数据、运维、租户、代码生成、AI 和示例能力的具体实现。

## 1. 用户、角色与权限

| 功能 | 前端入口 / moduleCode | 后端实现 | 关键行为 |
|---|---|---|---|
| 用户管理 | `views/system/privilege/user` / `SM_USER_MNG` | `SmUserController` → `SmUsersServices` | 专用 FormPage；头像上传、重置密码、关联角色 |
| 角色管理 | `views/system/privilege/role` / `SM_ROLE_MNG` | `SmRolesController`（显式路由 `/api/SmRole`）→ `SmRolesServices` | 列表维护和权限设置 |
| 用户角色 | 用户 FormPage | `SmUserRoleController` → `SmUserRoleServices` | QueryRole、QueryUserRole、BatchInsertUserRole |
| 角色菜单 | `PermissionSet.tsx` | `SmRoleModuleController` → `SmRoleModuleServices` | 获取全量模块树、已选模块、更新角色模块 |
| 数据范围 | `PermissionSet.tsx` | `SmRoleDataScopeController` → `SmRoleDataScopeServices` | 获取范围树、角色范围、用户范围并更新 |
| 功能权限定义 | `views/system/privilege/function` / `SM_FUNCTION_PRIVILEGE_MNG` | `SmFunctionPrivilegeController` → Service | 定义 Action/Menu/HideMenu/Custom 等动作 |
| 角色功能关系 | 无独立显式页面，嵌入权限配置 | `SmRoleFunctionController` → Service | 连接角色、模块基础 ActionCode 和功能 ID |
| 权限缓存清理 | `views/system/privilege/clear` | `GET /api/Common/ClearCache` → `Utility.ReInitCache` | 重建公共缓存；不是只清浏览器缓存 |

## 2. 模块、SQL 与栏位配置

| 功能 | 页面 | 后端实现 | 具体说明 |
|---|---|---|---|
| 模块树/列表 | `views/system/privilege/module/index.tsx` / `SM_MODULE_MNG` | `SmModulesController` / `SmModulesServices` | 标准 CRUD、菜单数据、授权菜单、模块聚合 |
| 模块表单 | `FormPage.tsx` | `SmModules` Entity/DTO/Input | 配置 ModuleCode、ApiUrl、页面、打开方式、能力开关、操作列位置、自定义列开关等 |

| 栏位设计 | `ColumnFormPage.tsx` 与 `views/system/config/form` | `SmModuleColumnController`、`SmModulesController.UpdateColumn/UpdateTaxisNo/AddColumn` | 列表和表单字段、控件、查询、校验、数据源、顺序 |

静态特性核对发现以下入口明确使用 `AllowAnonymous`：

| 分类 | 入口 |
|---|---|

| 文件读取/下载 | `/api/File/GetByUrl`、`/api/File/Img/{id}`、`/api/File/Download/{id}`、导入模板 Download |
| AI 文件 | `/api/Stream/Upload`；匿名调用 `AnalysisUploadAsync`，当前只判空，未限制大小/类型/`filePath`，请求文件名直接参与落盘路径 |
| 服务器/访问统计 | `ServerController.Get`、整个 `MonitorController` |

## 7. DbFirst、CodeFirst 与代码生成

- `DbFirstController`：读取数据库元数据并生成分层代码，属于工具链接口。
- `DynamicCodeFirstController`：动态建表、查询和插入测试，状态为 `EXAMPLE`。
- `Src/EU.CodeGenerator/**`：独立代码生成项目及模板。
- `DataBaseController`：数据库配置、表列读取和备注维护，不等于业务数据管理。

仓库中大量 Entity、DTO、Controller 和 Service 具有生成结构。修改生成结果前必须确认模板和手写扩展点，不能批量再生成整个仓库。

## 8. AI、MCP 与实时通信

### 前端 Chat

`components/Chat/Main.tsx`：

- 从缓存读取或生成 `chatId`。
- 请求 `${VITE_API_URL}/api/Stream/chat/{chatId}`。
- 渲染欢迎页、消息、Markdown、思考内容、文件卡片和流式事件。
- 文件通过 `/api/Stream/Upload` 上传，成功后把 `fileId` 传入消息；该匿名入口当前缺少大小、扩展名与目标路径约束，不能视为已经完成安全上传校验。

### 主 API Stream

`StreamController.HandleStreamRequest`：

1. 校验 Bearer Header。
2. 创建连接 `http://mcp`（Unix）或 `http://localhost:8020`（其他环境）的 MCP Client。
3. 目标端点为 `/Supplier/mcp`，并转发原 Authorization Header。
4. 获取 Supplier MCP 工具列表。
5. 调用 `ChatHelper.CallStreamAsync`，按 `event/data/id` 的 SSE 格式写回。
6. 使用 `RequestAborted` 处理中断。

当前 MCP 业务范围：

| 工具 | 当前方法实际行为 |
|---|---|
| `get_supplier` | 返回 `BD_SUPPLIER_MNG` 的 `module_list` 导航结果 |
| `create_supplier` | 返回该模块的 `module_edit` 导航结果，不直接写数据库 |
| `create_supplier_from_file` | 当前只返回带固定 ID 的 `module_edit` 结果，未解析 fileId 或创建数据，与 Attribute 描述不一致 |
| `update_supplier` | 按 supplierId/supplierNo 查询供应商，存在时返回带记录 ID 的编辑导航，不直接保存修改 |
| `delete_supplier` | 查询供应商后调用供应商 Service 删除，属于真实写操作 |
| `get_supplier_import_template` | 查询供应商模块导入模板及其附件并返回文件信息 |

### SignalR

主 API 注册 SignalR 并映射 `ChatHub` 到 `/chat`。前端 `layouts/index.tsx` 启动连接并注册 OnConnected、OnHeartbeat、OnReceiveMessage、OnConsole 与 onclose；当前 effect 没有依赖数组和卸载清理，重复渲染可能重复连接/注册监听。`SignalRTestController` 是测试入口，不应作为业务接口承诺。

## 9. 网关、任务和消息

- Gateway 读取 Ocelot 配置并固定监听 `9000`，当前注册 Ocelot + Polly；仓库虽有 `Ocelot.Provider.Nacos`，但 Gateway 的 `AddNacosDiscovery()` 被注释。主 API 的 Nacos 注册/配置监听是另一条可选宿主链路。
- Jobs 启动时检查数据库和 RabbitMQ；`MqttBroker.Enabled` 为真时启动已注册 HostedService。
- `TaskCenter` 通过 `ISchedulerCenter` 启动 Quartz 任务中心。
- `SchedulerCenterServer` 当前把调度器保存为 `Task<IScheduler>`，随后多处通过 `_scheduler.Result` 访问；任务初始化也有 `AddScheduleJobAsync(...).Result`，属于同步阻塞异步结果的既有风险。
- `Src/EU.Core.EventBus` 使用 `InMemoryEventBusSubscriptionsManager` 管理订阅关系，并包含 RabbitMQ、Kafka 两种传输；`EventBusSetup` 根据 `EventBus.Enabled`、`RabbitMQ.Enabled`、`Kafka.Enabled` 注册，当前未发现 Channel/Redis EventBus Provider。
- `EventBusHostedService` 在事件总线开启时直接解析单个 `IEventBus`：至少要启用一种传输；RabbitMQ 与 Kafka 同时开启时，Microsoft DI 的单服务解析会取得后注册的 Kafka，实现并不是自动双写。
- Serilog 由主 API 宿主注册，包含请求日志管道；其他宿主需分别确认自己的日志注册。
