# EU-Admin 开发与交付导航

> 状态：`CURRENT`
>
> 用途：从需求定位到拥有路径、影响范围、验证和文档维护。
>
> 强制规则仍以根及局部 `AGENTS.md` 为准。
> 返回：[项目说明索引](README.md)

## 1. 开始任务前

1. 运行 `git status --short`，保护已有改动。
2. 按根 `AGENTS.md` 分类任务：FRONTEND、BACKEND-BUSINESS、BACKEND-PLATFORM、BACKEND-HOST、API-CONTRACT、CROSS-END-CONTRACT、DATABASE、DOCS 等。
3. 从[功能模块地图](功能模块地图.md)找到拥有路径。
4. 读取对应局部 `AGENTS.md`、专题 README、相邻实现、类型和配置。
5. 明确用户可见行为、权威状态、生产者/消费者、失败语义和验证范围。

## 2. 需求到拥有路径

| 需求信号 | 首选拥有路径 | 不应直接放入 |
|---|---|---|
| 普通业务页面 | `src/views/<domain>` + `src/api` | layouts、全局 Redux |
| 动态列表/表单 | SmModule 配置 + ProTable/Elements | 页面内自建 Axios/重复 CRUD |
| 页面/按钮权限 | auth/user/module Redux + 服务端 SM 权限链 | 仅用 CSS 隐藏 |
| 新 API/DTO | Controller + IService + Service + Model | React 页面、Repository HTTP 语义 |
| 业务规则/状态流转 | 对应领域 Service | Controller 或前端判断代替 |
| 数据访问 | Repository/DataAccess | Controller 临时连接数据库 |
| 公共缓存/认证/租户 | Common/Extensions/DataAccess | 单一业务补丁 |
| 后台任务 | Jobs + Tasks + 业务服务 | Web 请求内长时间阻塞 |
| 网关/Nacos | Gateway 宿主 | Web API Program 顺手注册 |
| MCP/AI | MCP API + Stream 边界 + Chat 消费者 | 普通 CRUD 响应假设 |
| 数据库字段 | 实体/DTO/映射/SQL/消费者/文档 | 只改 TypeScript 或只改 SQL |
| 代码生成 | `EU.CodeGenerator`、模板和生成流程 | 批量手改生成结果后不说明 |

## 3. 常见修改路线

### 3.1 新增动态业务模块

1. 确定唯一稳定的 ModuleCode。
2. 建立 `SmModules` 页面和能力配置。
3. 建立 `SmModuleSql` 查询模型。
4. 建立 `SmModuleColumn` 列表/搜索/表单字段。
5. 配置角色模块、基础 ActionCode 和功能按钮。
6. 复用通用 TableList/FormPage；复杂行为再创建领域页面。
7. 验证缓存刷新、空配置、无权限、主从关系和导入导出。

### 3.2 新增复杂业务单据

1. 明确主表、明细、候选来源、状态和下游单据。
2. 建立 Entity、DTO、Insert/Edit Input 和映射。
3. IService 定义业务动作，Service 实现事务、权限、幂等和状态规则。
4. Controller 只拥有 HTTP 边界。
5. 前端领域页面编排主从表、候选弹窗和批量动作。
6. 同步 SmModule 列、按钮权限、日志、导入导出和文档。
7. 测试成功、无权、无效状态、重复提交、空明细、并发和回滚。

### 3.3 修改 API 契约

1. 标记 `API-CONTRACT`；仓库内前端同步修改时标记 `CROSS-END-CONTRACT`。
2. 列出路由、方法、认证、参数、字段、类型、可空性、分页和响应包装变化。
3. 搜索所有 Controller/Service/Model 和 `src/api/**`、页面、Redux 消费者。
4. 优先兼容扩展；破坏性变化说明上线顺序和回滚。
5. 至少完成后端构建/测试和前端类型检查。

### 3.4 修改数据库

1. 标记 `DATABASE`，完整阅读数据库表设计约束。
2. 同步实体、DTO、ORM、仓储、服务、接口、前端类型和文档。
3. 考虑多数据库方言、默认值、可空性、索引和审计字段。
4. 提供可审查、可重复执行或边界明确的迁移及回滚。
5. 未经明确授权不连接、迁移或写入任何数据库。

### 3.5 修改权限、租户或安全边界

- 核对认证特性、策略、角色、功能权限、数据范围和租户过滤。
- 加入无权限、跨租户、过期令牌、伪造参数等负向验证。
- 不为通过测试绕过过滤器或授权。
- 不输出真实 Token、密码、连接串、日志个人数据。

## 4. 横切影响矩阵

| 如果修改 | 同时检查 |
|---|---|
| 用户或登录 | AuthorizeController、SmUsersService、user/auth Redux、请求 Header、菜单与登出清理 |
| 菜单/路由 | SmModules、角色模块、ConvertRouter、RouterGuard、Tabs/KeepAlive、直接访问 |
| ModuleInfo | 后端组装、前端类型、Redux 缓存、ProTable、Elements、EditableTable |
| 表格列 | 查询字段、列增强、用户列偏好、导入导出、合计、移动端/流程条件 |
| 表单控件 | CompDatas、Elements 映射、Form 字段模型、校验、设计器、文档 |
| 工作流节点 | 两套 workflow 边界、后端 WorkFlow DTO/Service、发布和历史数据兼容 |
| 单据转单 | 来源状态、目标主从数据、事务、重复提交、权限和下游库存 |
| 文件上传 | 大小/类型/文件名、路径、分片、附件关系、下载鉴权和清理 |
| 缓存 | key owner、用户/租户隔离、TTL、刷新、并发和回源失败 |
| 事件/任务 | 幂等、重试、取消、异常观测、宿主停止和资源释放 |
| 配置/环境变量 | 所有宿主、前端暴露范围、默认值、部署文档和回滚 |
| CORS | `Startup:Cors:EnableAllIPs`、来源白名单、凭据策略和网关暴露范围；生产不应无评审地使用开放模式 |
| EventBus | `EventBus.Enabled` 与 RabbitMQ/Kafka 开关组合；不得在无 Provider 时只开启 EventBus，同时开启两种 Provider 时需确认单 `IEventBus` 实际解析 Kafka |

## 5. 验证门禁

### 前端

```text
cd eu.admin.react
pnpm type:check
pnpm build:dev       # 需要开发环境构建验证时
pnpm build:test      # 测试环境发布变更时
pnpm build           # 生产构建或发布变更时
```

ESLint、Prettier、Stylelint 脚本会自动修复；运行前必须限制作用域并保护用户改动。当前没有统一前端 `test` 脚本。

### 后端

```text
dotnet build eu.core/EU.Core.sln
```

范围明确时可先构建受影响项目。运行测试前检查 fixture 和配置；会连接 Redis、MongoDB、SQL、消息队列或外部 HTTP 的测试只能在隔离环境和明确授权下运行。

### 跨端与数据库

- API 契约：后端构建/测试 + 前端类型检查。
- 数据库：隔离数据库、迁移/回滚、实体映射与真实请求响应。
- 权限/租户：正向与负向边界。
- 宿主：分别启动 API、Jobs、Gateway、MCP，不互相替代。

### 所有任务

```text
git diff --check
git status --short
```

## 6. 文档维护规范

### 分层

- L0：根及局部 `AGENTS.md`，只放强制约束和阅读路由。
- L1：`doc/readme.md` 与本项目说明索引，回答“去哪里”。
- L2：架构总览、功能模块地图、开发与交付，回答稳定边界。
- L3：`doc/frontend/**`、`doc/backend/**`、源码旁 README，回答专题细节。
- 历史/计划：HTML 分析报告、设计计划，应标明状态，不能高于当前源码。

### 必须更新文档的变化

- 新增、删除或移动稳定模块。
- 修改 API、DTO、路由、权限、租户、缓存、数据库或宿主生命周期。
- 修改用户可见业务规则、单据状态或转单链路。
- 修改 SmModule、工作流、低代码、导入导出或文件协议。
- 修改环境变量、构建、部署和外部依赖。

### 写作规则

- 开头写状态、适用范围和返回索引。
- `CURRENT` 只描述已落地行为；计划明确写 `PLANNED`。
- 用仓库相对路径链接拥有目录，不复制大段源码。
- 一项事实只选择一个主要 owner，其余文档摘要并链接。
- 不记录真实凭据、生产地址中的秘密信息或个人数据。

## 7. 交付说明模板

最终说明至少包含：

- 任务分类与拥有路径。
