# EU-Admin 实现链路与源码索引

> 状态：`CURRENT`
>
> 核对日期：2026-08-09
>
> 用途：把功能说明落实到前端组件、API、Controller、Service 和模型。最终菜单 URL、模块 API 地址和租户可见性仍以运行环境中的 `SmModules` 配置为准。

## 1. 阅读约定

- 本文记录仓库当前实现，不把文件名、历史代码或示例端点自动视为生产能力。
- `BaseController` 继承链提供的接口只列一次；业务表格中的“标准 CRUD”均指该公共契约。
- React 业务路由由授权菜单动态生成。文档记录组件路径和 `moduleCode`，不猜测数据库里的最终 `RouteUrl`。
- Controller 默认路由中的 `[controller]` 取 C# 类名而不是文件名。例如 `FileAttachmentController.cs` 内的类名是 `FileController`，其基础路由是 `/api/File`。

### 动态路由真实链路

```text
token 已存在
  → usePermissions.initPermissions()
  → GET /api/SmModule/GetAuthMenu
  → SmModulesController.GetAuthMenu()
  → SmModulesServices.GetAuthMenu()
  → 用户角色/模块关系 + UserAuthMenu Redis 缓存
  → auth Redux
  → ConvertRouter 将 element 字符串映射到 src/views/**/*.tsx
  → RouterGuard 包装页面
```

实现边界：最终路径、页面组件字符串、菜单显隐及角色可见性由数据库模块数据决定，单看 React 源码无法还原某个部署环境的完整菜单树。

## 3. 登录、会话与请求层

| 功能 | 前端实现 | 后端实现 | 已核对行为 |
|---|---|---|---|
| 登录 | `views/login/components/LoginForm.tsx` → `api/modules/login.ts::loginApi` | `AuthorizeController.Login` → `ISmUsersServices.LoginAsync` | `POST /api/Authorize/Login`；成功后写入 token 与 `UserInfo` |
| 当前用户 | `layouts/.../UserName.tsx` | `AuthorizeController.CurrentUser` → `CurrentUserAsync` | Header 挂载时请求 `GET /api/Authorize/CurrentUser`，不是 RouterGuard 主动恢复用户 |
| 修改本人密码 | Header 密码弹窗 | `AuthorizeController.RestPassword` | `PUT /api/Authorize/RestPassword`；方法名保持现有拼写 `RestPassword` |
| 管理员重置密码 | 用户管理页/模块动作 | `SmUserController.ResetPassword` | `PUT /api/SmUser/ResetPassword/{id}` |
| 退出 | `AvatarIcon.tsx` → `logoutApi` | `AuthorizeController.LogOut` | `GET /api/Authorize/LogOut`；成功后清用户资料、token、授权菜单并跳登录，未直接清 module/tabs Redux |
| 开发测试 Token | 无生产页面入口 | `AuthorizeController.GetAccessToken` → `SmUsersServices.GetAccessToken` | `GET /api/Authorize/GetAccessToken` 标记 `AllowAnonymous`；查找预设系统管理员并生成 2099 年到期 Token，Service 已标记 Obsolete 并警告生产禁用 |

[`src/api/index.ts`](../../eu.admin.react/src/api/index.ts) 创建唯一 Axios 实例：

- `baseURL` 来自 `VITE_API_URL`，超时来自 `ResultEnum.TIMEOUT`。
- 请求拦截器写入 `Authorization: Bearer <token>`；动态列表的 filter 被 URI 编码后写入 `filter` Header。
- 响应拦截器直接返回响应体；业务 `Status` 非成功时统一提示，过期状态会清 token 并跳转登录。
- `getGridList` 与普通 `get` 使用同一 Axios 实例，但 TypeScript 返回类型分别为分页和普通响应。

Redux 持久化配置位于 `src/redux/index.ts`。`auth`、`module`、`workflow`、`formDesign`、`mobileEditor` 被列入 blacklist，不跨刷新持久化；token/user/global/tabs 等其余状态遵循当前 persist 配置。

## 4. 标准 Controller 契约

[`BaseController.cs`](../../eu.core/EU.Core.Api/Controllers/Base/BaseController.cs) 通过反射调用具体 Service。所有继承它且未重写方法的 Controller 自动具有：

| HTTP | 相对路由 | Service 方法 | 用途 |
|---|---|---|---|
| GET | `QueryByFilter` | `QueryFilterPage` | DTO 分页查询 |
| GET | `{Id}` | `QueryById` | 主键详情 |
| GET | `GetPageList` | `GetPageList` | 兼容 paramData/sorter/filter 的列表入口 |
| POST | 空 | `Add` | 单条新增，Controller 接收 `object` |
| POST | `BulkInsert` | `Add(List<TInsertDto>)` | 批量新增 |
| PUT | `{Id}` | `Update` | 更新 |
| PUT | `UpdateReturn/{Id}` | `UpdateReturn` | 更新并返回更新后的对象，EditableProTable 使用 |
| DELETE | `{Id}` | `AnyAsync`、`Delete` | 单条删除 |
| DELETE | 空 | `Delete(Guid[])` | 批量删除 |
| PUT | `Audit/{Id}` / `BulkAudit` | `Audit` / `BulkAudit` | 审核 |
| PUT | `Revocation/{Id}` / `BulkRevocation` | `Revocation` / `BulkRevocation` | 撤销 |

这套 Controller 通过 `InvokeServiceAsync` 反射定位方法，具体 Service 必须保留相同方法名和兼容参数。业务 Controller 的自定义动作是在此契约之上追加，而不是替代标准 CRUD。

## 5. 元数据驱动页面链路

### 5.1 页面入口

大多数简单页面只传一个 `moduleCode`：

```tsx
return <Main moduleCode="BD_COLOR_MNG" />;
```

[`views/system/common/main.tsx`](../../eu.admin.react/src/views/system/common/main.tsx) 的行为是：

1. 从 `redux/modules/module.ts` 读取 `moduleInfos[moduleCode]`。
2. 缓存未命中时调用 `GET /api/SmModule/GetModuleInfo/{moduleCode}`。
3. 成功后写入 Redux，再渲染 `FormIndex`。
4. 加载期间显示 Skeleton。

### 5.2 模块信息组装

`SmModulesController.GetModuleInfo` 委托 `SmModulesServices.GetModuleInfo`，返回的核心字段及来源如下：

| 返回字段 | 后端来源/算法 | 前端消费者 |
|---|---|---|
| `columns` | `GetModuleColumn`，由模块 SQL 栏位和用户偏好组装 | ProTable |
| `formColumns` | `ModuleSqlColumn.GetModuleSqlColumn()`；排除纯 list 字段并按 `FormTaxisNo` 排序 | 动态 FormPage |
| `actions` | 用户角色功能中的基础 `ActionCode`，再受模块 `IsShow*` 开关过滤 | Toolbar、批量操作 |
| `actionData/menuData/hideMenu/customActionData` | `SmFunctionPrivilege.DisplayPosition` 分组 | 行操作、工具栏和扩展动作 |
| `beforeActions/dropActions` | 操作数大于 3 时前 2 个平铺，其余下拉；否则最多 3 个平铺 | ProTable 操作列 |
| `children/masterColumn/isDetail` | 下级模块和主从栏位配置 | 主从表过滤、详情页 |
| `openType/formPage/formPageWidth` | `SmModules` | 页面、Modal、Drawer 及宽度 |
| `url` | `SmModules.ApiUrl` | 通用详情、新增、更新、删除 |
| `UserModuleColumn` | `SmUserModuleColumn` 与用户级 Redis 缓存 | 列顺序、显隐、宽度等 |
| `optionPosition` | `OptionPosition == "right" ? "right" : "left"` | 操作列固定在左或右 |
| `isAllowCustomColumn` | `IsAllowCustomColumn != false` | 控制 ProTable `options.setting` |

### 5.3 列表查询

```text
SmProTable/useProTableData
  → queryByFilter(moduleCode, params, filter)
  → GET /api/Common/QueryByFilter/{moduleCode}
  → CommonController.QueryByFilter
  → CommonServices.QueryByFilter
  → ModuleInfo + ModuleSqlColumn + ModuleSql + GridList
  → SqlSugar ADO 执行分页 SQL
```

`CommonServices.QueryByFilter` 当前具体处理：

- 从查询参数构造栏位条件，并追加 `filter.Conditions`。
- 按可搜索栏位构造 `keyWord` 条件。
- 读取模块 Select/Table/Join/默认条件/排序配置。
- 替换 SQL 中的 `[USER_ID]`。
- 非 Admin 用户在模块启用角色数据范围时追加 `A.CompanyId` 范围条件。
- 执行 count 和分页 SQL，再按模块规则格式化树结构。

`customConditions` 和主从表 Conditions 最终进入服务端查询条件；它们属于敏感边界，调用方不能把未校验的用户文本直接拼成条件。

### 5.4 列表交互

| 交互 | 具体实现 |
|---|---|
| 列渲染 | `hooks/ProTable/useProTableColumns.tsx` 与 `components/ProTable/columnCustomizers.tsx` |
| 查询状态 | `useProTableData.ts` 保存分页、排序和搜索参数到 module Redux |
| 批量删除/审核/撤销 | `useProTableBatchOps.tsx` → 模块 `url` 的 DELETE、`BulkAudit`、`BulkRevocation` |
| 导出 | `useProTableToolbar.ts` → `GET /api/Common/ExportExcel/{moduleCode}`，返回文件 ID |
| 用户列偏好 | `recordUserModuleColumn` → `POST /api/SmModule/RecordUserModuleColumn/{moduleId}` |
| 操作列位置 | `components/ProTable/index.tsx` 用 `optionPosition` 同时决定列插入位置和 `fixed` 方向 |
| 自定义列开关 | ProTable 与 EditableProTable 用 `isAllowCustomColumn !== false` 决定是否显示 setting |
| 双击编辑 | 非汇总行、非查看态且具有 Update 操作时触发 `onOptionEdit` |
| 跨页选择 | `preserveSelectedRowKeys: true`；汇总行 ID 被禁选 |

### 5.5 动态表单

`TableList` 根据 `openType` 决定 Modal、Drawer 或由专用页面 `changePage` 切换；默认表单为 `components/Elements/FormPage.tsx`，专用业务可通过 `DynamicFormPage` 替换。

默认表单调用链：

```text
查看/编辑 → querySingle({ url, Id }) → GET {moduleInfo.url}/{Id}
新增     → add({ url, ModuleCode, ...fields }) → POST {moduleInfo.url}
更新     → update({ url, Id, ModuleCode, ...fields }) → PUT {moduleInfo.url}/{Id}
```

字段组件位于 `components/Elements`；`formColumns` 决定控件、标题、隐藏、只读、数据源、默认值和校验。主从表表单通过 `masterColumn`、`masterId` 回填关联字段。

## 7. 表单设计、移动页面和工作流

### PC 栏位设计

- `FormDesign.tsx` 调用 `GET /api/SmModule/FormColumn/{moduleId}` 获取可设计栏位。
- 字段属性保存调用 `PUT /api/SmModule/UpdateColumn/{moduleCode}/{mode}`。
- 列表/表单拖拽排序调用 `PUT /api/SmModule/UpdateTaxisNo/{moduleCode}/list|form`。
- 新增栏位调用 `POST /api/SmModule/AddColumn/{moduleCode}`。
- `SmModulesServices` 写入后更新模块/栏位相关缓存，避免继续返回旧元数据。

### 移动页面

- 前端编辑器：`views/system/config/mobile/editor/**`，Redux：`redux/modules/mobileEditor.ts`；后端为 `SmMobilePageConfigController` / `SmMobilePageConfigServices`。
- 标准 CRUD：`/api/SmMobilePageConfig`。
- 发布：`POST /api/SmMobilePageConfig/Publish/{id}`。
- 读取已发布页面：`GET /api/SmMobilePageConfig/Page/{pageCode}?appScope=...`。
- 当前 `api/modules/mobileConfig.ts::getMobilePageList` 使用普通数组泛型调用分页接口，返回类型与 `BaseController.QueryByFilter` 的分页包装需在真实联调时再次确认。

### 工作流

- 业务设计器：`src/workflow/**`；另一套编辑器引擎：`src/workflow-editor/**`。
- 工作流定义标准 CRUD 由 `SmWorkFlowController` 继承获得。
- 发布节点树：`POST /api/SmWorkFlow/Publish/{id}`。
- 按流程读取：`GET /api/SmWorkFlow/QueryNode/{id}`。
- 按模块获取流程：`GET /api/SmWorkFlow/ForModule/{moduleId}`。
- 按模块获取节点：`GET /api/SmWorkFlow/QueryNodeByModule/{moduleId}`。
- `SmWorkFlowNodeController` 与 `SmWorkFlowNodeAuditController` 管理节点和节点审核数据。

## 9. 独立宿主的实际入口

| 宿主 | 启动代码 | 当前实现事实 |
|---|---|---|
| 主 API | `EU.Core.Api/Program.cs` | Autofac、数据库、缓存/Nacos、Redis MQ、SignalR、认证授权、Swagger、Serilog；映射 `/chat` Hub |
| Jobs | `EU.Core.Jobs/Program.cs` | 检查数据库和 RabbitMQ；可选启动 MQTT hosted services；启动 `TaskCenter` 后等待停止信号 |

MCP 当前不是“所有业务域的通用工具平台”：仓库可确认的工具只在 `SupplierService`。`get_supplier`、`create_supplier` 返回模块导航；`update_supplier` 查询目标后返回编辑导航；`delete_supplier` 实际调用删除服务；`get_supplier_import_template` 查询模板附件。“从文件创建”当前方法只返回带固定记录 ID 的编辑导航，并没有执行其工具描述声称的文件解析与批量创建。主 API 的 `POST /api/Stream/chat/{chatId}` 创建 MCP Client 连接 `/Supplier/mcp`，传递 Bearer Header，再把 AI 事件按 SSE 写回前端。

## 10. 实现风险与维护提示

- `TableList` 会对模块返回的 `FunctionJs` 使用 `eval`；只有受信任管理员可维护这些脚本，并应把它视为可执行代码边界。
- `SmModulesServices.GetModuleInfo` 捕获异常后仍构造 `Success = true`，错误主要体现在 `message`；消费者不能只依赖 Success 判断模块是否完整。
- `CommonController` 中存在标记 `AllowAnonymous` 的生成、同步、初始化和测试入口；它们应按工具/历史端点管理，不能在文档中描述为普通用户功能。
- AI 文件上传和部分图片读取同样是匿名端点；其中 `AnalysisUploadAsync` 未复用现有上传校验，文件大小、类型、目标目录和文件名处理均需单独安全评审。
- `SdOrderController111.cs` 被项目文件排除编译；`FormPage.old.tsx`、Redis 示例和 DynamicCodeFirst 属于历史/示例实现，不作为当前主链路。
- 当前退出流程未直接清理 module/tabs Redux；虽然 module 不持久化，但同一页面生命周期内的账号切换仍需回归残留状态。
- `layouts/index.tsx` 的 SignalR `useEffect` 没有依赖数组，每次渲染都会再次调用 connect 并注册事件/onclose；同时没有卸载清理，可能产生重复监听和重连计时器。
