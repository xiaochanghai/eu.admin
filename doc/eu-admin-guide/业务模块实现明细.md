# EU-Admin 业务模块实现明细

> 状态：`CURRENT`
>
> 用途：按业务域记录页面组件、模块代码、后端分层和非标准动作。

## 1. 公共约定

下表中的每个生产 Controller 若继承 `BaseController`，默认都具备查询、详情、新增、批量新增、更新、更新并返回、删除、批量删除、审核和撤销接口。表格只额外写业务动作。

标准后端链路命名为：

```text
<Domain>Controller
  → I<Domain>Services
  → <Domain>Services
  → IRepository/<Domain>Repository 或 BaseRepository
  → Entity/<Domain> + DTO/Insert/Edit
```

前端业务页面先用 `moduleCode` 获取 `ModuleInfo.url`，标准 CRUD 不在页面中硬编码 Controller 基础地址；只有转单、过账、完结、候选数据等领域动作直接调用明确接口。

## 3. 采购 PO

### 3.1 模块和调用链

| 单据 | 主/明细 moduleCode | 页面 | Controller → Service | 自定义动作 |
|---|---|---|---|---|
| 采购申请 | `PO_REQUESTION_MNG` / `PO_REQUESTION_DETAIL_MNG` | `views/purchase/requestion` | `PoRequestionController` / `PoRequestionDetailController` → 同名 Services | `POST /api/PoRequestion/BulkOrderComplete` |
| 采购订单 | `PO_ORDER_MNG` / `PO_ORDER_DETAIL_MNG` | `views/purchase/order` | `PoOrderController` / `PoOrderDetailController` | 后端提供 `BulkInsertNotice`、`BulkInsertIn`；当前页面的 `PurchaseOrderChange` 却调用销售接口 `/api/SdOrder/BulkOrderChange`，属于待确认实现 |
| 到货/通知 | `PO_ARRIVAL_ORDER_MNG` / `PO_ARRIVAL_ORDER_DETAIL_MNG` | `views/purchase/notice` | `PoArrivalOrderController` / `PoArrivalOrderDetailController` | `BulkInsertDetail/{id}`、`BulkInsertIn`、`BulkOrderComplete` |
| 采购入库 | `PO_IN_ORDER_MNG` / `PO_IN_ORDER_DETAIL_MNG` | `views/purchase/in` | `PoInOrderController` / `PoInOrderDetailController` | `BulkInsertDetail/{id}`、`BulkOrderComplete`、`CarryTo` |
| 采购退货 | `PO_RETURN_ORDER_MNG` / `PO_RETURN_ORDER_DETAIL_MNG` | `views/purchase/return` | `PoReturnOrderController` / `PoReturnOrderDetailController` | 后端提供 `BulkOrderComplete`、`CarryTo`；当前页面的完结回调实际调用 `/api/PoInOrder/BulkOrderComplete`，没有调用退货完结接口 |

### 3.2 候选数据模块

| moduleCode | 消费页面 | 作用 |
|---|---|---|
| `PO_ORDER_WAIT_REQUESTION_MNG` | 采购订单 `MaterialQuery.tsx` | 查询待转采购订单的申请明细 |
| `PO_ORDER_WAIT_NOTICE_MNG` | 采购订单/通知选择页 | 查询待生成通知单的订单数据 |
| `PO_ORDER_WAIT_IN_MNG` | 采购订单/入库选择页 | 查询可直接生成入库的订单数据 |
| `PO_NOTICE_ORDER_WAIT_IN_MNG` | 通知/入库选择页 | 查询待入库通知明细 |
| `PO_IN_ORDER_WAIT_RETURN_MNG` | 采购退货 `MaterialQuery.tsx` | 查询可退货的采购入库明细 |
| `BD_MATERIAL_SELECT_MNG` | 订单、退货物料选择 | 通用物料候选列表 |

### 3.3 状态传播

- `PoArrivalOrderServices.BulkInsertInAsync` 创建入库来源数据；`BulkOrderComplete` 完结到货单。
- `PoArrivalOrderDetailServices.UpdatePurchaseOrderStatus` 回写采购订单状态。
- `PoInOrderDetailServices.UpdateSourceOrderStatus` 按 `orderSource` 回写来源单据。
- `PoOrderServices.UpdatePoOrderStatus` 根据转通知/入库类型刷新订单状态。
- `PoReturnOrderDetailServices.UpdateSourceOrderStatus` 回写退货来源。

因此修改采购明细数量、来源 ID、状态字段或完结规则时，必须同时检查主单、明细、候选查询模块和下游单据 Service。

当前采购前端有两处静态调用与页面领域不一致：采购订单“变更”调用销售订单变更接口，采购退货“完结”调用采购入库完结接口。本文按源码如实记录，不把这两条调用描述为正确业务行为；是否为数据库 `FunctionJs` 命名复用或复制遗留，需要在隔离环境结合菜单动作配置确认。

| 发货单 | `SD_SHIP_ORDER_MNG` / `SD_SHIP_ORDER_DETAIL_MNG` | `views/sales/shipOrder` | `SdShipOrderController` / `SdShipOrderDetailController` | `BulkInsertDetail/{id}`、`BulkOrderComplete`、`BulkInsertOut` |

| 销售退货 | `SD_RETURN_ORDER_MNG` / `SD_RETURN_ORDER_DETAIL_MNG` | `views/sales/returnOrder` | `SdReturnOrderController` / `SdReturnOrderDetailController` | `BulkInsertDetail/{orderId}`、`CarryTo` |

候选模块：

- `SD_SALES_ORDER_WAIT_SHIP_MNG`：订单待发货。
- `SD_SALES_ORDER_WAIT_OUT_MNG`：订单待直接出库。
- `SD_SALES_SHIP_ORDER_WAIT_OUT_MNG`：发货单待出库。
- `SD_SALES_ORDER_WAIT_RETURN_MNG`：销售订单/出库待退货。
- `BD_MATERIAL_SELECT_MNG`：销售物料选择。

状态回写位于 `SdShipOrderDetailServices.UpdateSalesOrderStatus`、`SdOutOrderDetailServices.UpdateSalesOrderStatus/UpdateShipOrderStatus`、`SdReturnOrderDetailServices.UpdateOutOrderStatus`。`SdOrderController111.cs` 的类名是 `OrderController`，且被 `EU.Core.Api.csproj` 排除编译，不纳入当前 `SdOrderController` 契约。

## 8. 修改业务链路时的检查点

| 改动 | 必查实现 |
|---|---|
| 主单字段 | 主 Entity/DTO/Insert/Edit、主 Service、专用 FormPage、模块栏位和导入导出 |
| 明细字段 | 明细 Entity/DTO/Service、EditableProTable、候选模块和主从关联字段 |
| 数量/金额 | 计算、汇总行、来源余量、下游带入、过账/完结和报表 SQL |
| 状态字段 | 自定义批量动作、按钮显隐、来源/下游状态回写、重复提交和事务 |
| 转单 | 候选 moduleCode、选择弹窗、Controller 自定义动作、Service 去重/余量/回写 |
| 删除 | 已转单/已过账限制、明细级联、来源状态回滚、审计和逻辑删除 |
