# EU-Admin 系统架构总览

> 状态：`CURRENT`
>
> 用途：说明前后端、独立宿主、元数据、权限、数据与基础设施的稳定边界。
> 返回：[项目说明索引](README.md)

## 1. 架构定位

EU-Admin 是一个前后端分离的企业管理平台。React 管理端负责用户交互、动态菜单、通用列表/表单和业务工作流；.NET 解决方案负责 HTTP 边界、业务规则、持久化、后台任务、网关、MCP/AI 与平台基础设施。

它同时采用两种页面开发模式：

- 元数据驱动：由 `SmModules`、`SmModuleSql`、`SmModuleColumn` 和权限配置组装通用列表、搜索与表单。
- 专用业务页面：采购、销售、库存、设备等复杂单据通过领域页面编排主从表、候选单据、状态动作和自定义 API。

两者共享 `src/api`、Redux、动态路由、权限、通用组件和服务端业务分层。

## 2. 前端分层

| 层 | 拥有路径 | 职责 |
|---|---|---|
| 启动与上下文 | `src/main.tsx`、`src/context/**`、`src/plugins/**` | React 启动、全局 Provider、应用级依赖初始化 |
| 路由与权限 | `src/routers/**`、`src/redux/modules/auth.ts`、`user.ts` | 静态路由、后端菜单转路由、路由守卫、权限状态 |
| 布局与导航 | `src/layouts/**`、`src/redux/modules/tabs.ts`、`global.ts` | 多布局、菜单、Header、标签页、主题、国际化、全屏 |
| 页面 | `src/views/**` | 系统和业务页面、专用表单、候选单据选择与详情 |
| 通用业务 UI | `src/components/**` | ProTable、动态表单、上传、图表、AI 对话、设计器、错误页 |
| 状态 | `src/redux/**` | 用户、权限、模块信息、表格参数、标签页、设计器和流程状态 |
| HTTP 边界 | `src/api/**` | Axios 实例、响应解包、状态检查和领域 API；`axiosCancel.ts` 已提供取消工具，但当前请求实例未接入 |
| 协调 Hook | `src/hooks/**` | 表格数据/列/工具栏、权限、主题、上传、剪贴板等生命周期逻辑 |
| 流程与低代码 | `src/workflow/**`、`src/workflow-editor/**`、`src/dsl/**` | 流程节点、设置器、编辑器引擎、DSL 与导入导出 |

### 前端状态权威

- 用户和令牌：`redux/modules/user.ts`。
- 菜单、页面和按钮权限：`redux/modules/auth.ts` 与后端授权菜单。
- 模块元数据和列表查询状态：`redux/modules/module.ts`，按 `moduleCode` 隔离。
- 标签页：`redux/modules/tabs.ts`。
- 主题、语言和布局：`redux/modules/global.ts`。
- 表单/移动端/流程设计器：各自 Redux 模块或编辑器 Context，不混入用户会话状态。

## 3. 后端分层与依赖方向

```text
Controller（HTTP、路由、授权、输入输出）
  ↓
IService（领域服务契约）
  ↓
Service（业务规则、状态动作、事务编排）
  ↓
Repository / DataAccess（查询与持久化）
  ↓
Model / Database（实体、DTO、输入输出、数据库）
```

| 项目 | 主要职责 |
|---|---|
| `EU.Core.Api` | 主业务 API、Swagger、过滤器、认证授权、文件、动态 CRUD、流式 AI 转发 |
| `EU.Core.IServices` | 服务接口和业务契约 |
| `EU.Core.Services` | 通用与领域业务逻辑、单据动作、模块聚合 |
| `EU.Core.Repository` | 仓储实现 |
| `EU.Core.Model` | 实体、DTO、输入输出模型、视图模型 |
| `Src/EU.Core.DataAccess` | SqlSugar/EF Core/Dapper 等数据库基础能力 |
| `Src/EU.Core.Common` | 模块元数据、缓存、租户、帮助类、种子与公共模型 |
| `Src/EU.Core.Extensions` | DI、认证、数据库、Swagger、消息与宿主扩展注册 |
| `Src/EU.Core.EventBus` | 内存订阅关系管理，以及 RabbitMQ/Kafka 事件传输实现 |
| `Src/EU.Core.Tasks` | Quartz、任务抽象与后台执行能力 |
| `Src/EU.Core.Serilog`、`Src/EU.Core.Serilog.Es` | 结构化日志及 Elasticsearch 扩展；后者项目名为 `EU.Core.Serilog.Es` |
| `Src/Ocelot.Provider.Nacos` | Ocelot 的 Nacos Provider 辅助项目；当前 Gateway 未启用其发现注册 |
| `Src/EU.CodeGenerator` | 代码生成器与模板 |
| `Src/EU.Core.Tests` | 单元/集成测试集合，部分测试依赖外部基础设施 |

后端普通业务不得让 Controller 直接拥有数据库访问，也不得让 Repository 承载 HTTP 或页面语义。

## 4. 独立宿主

| 宿主 | 入口 | 能力 | 生命周期边界 |
|---|---|---|---|
| Web API | `EU.Core.Api/Program.cs` | 业务接口、认证、Swagger、文件、SignalR/流式能力 | 主业务请求生命周期 |
| Jobs | `EU.Core.Jobs/Program.cs` | Quartz 和任务中心 | 长生命周期后台进程，需独立停止与异常观测 |
| MCP API | `EU.Core.MCP.Api/Program.cs`（项目程序集 `EU.Core.Api.MCP`） | MCP/AI 接口 | 独立认证、配置和运行端口 |
| Gateway | `Src/EU.Core.Gateway/Program.cs` | Ocelot 路由与 Polly；Nacos Provider 项目存在，但 Gateway 的 `AddNacosDiscovery()` 当前被注释 | 独立网关配置与健康状态 |

一个宿主中的 DI、配置或中间件不会自动出现在其他宿主；修改公共平台能力时必须逐个检查引用和启动路径。

## 5. 认证、授权和会话

### 认证链路

1. 登录页通过 `src/api/modules/login.ts` 调用授权接口。
2. 后端 `AuthorizeController` 委托用户服务校验账号并签发登录结果。
3. 前端保存用户/令牌状态，请求层携带认证信息。
4. Header 的当前用户接口补齐用户资料；当前退出实现清理用户、token 和授权菜单。module/tabs 没有在 `AvatarIcon` 中直接清理，账号切换场景需要特别关注残留状态。

认证扩展根据配置在内置 JWT、IdentityServer4 和 Authing 三种注册路径中选择，并禁止同时启用 IdentityServer4 与 Authing；实际入口以宿主配置和 Controller 特性为准。

当前 `EU.Core.Api/Program.cs` 无条件设置 `IdentityModelEventSource.ShowPII = true`，而按开发环境控制的写法被注释。该设置会增加身份诊断日志中的敏感细节，生产部署需要关闭或通过环境策略限制日志暴露。

CORS 由 `Startup:Cors` 配置控制：受限模式使用 `IPs` 白名单；`EnableAllIPs=true` 时通过 `SetIsOriginAllowed` 接受任意来源，并允许任意方法、Header 和凭据。开放模式属于高风险部署选项，必须结合 Cookie/Token、网关和公网暴露范围评审。

### 授权层次

- 页面/菜单：后端授权菜单 → 前端动态路由。
- 基础操作：模块的 Add/Update/Delete/View/Submit/BatchDelete 等 ActionCode。
- 功能按钮：`SmFunctionPrivilege` 与角色功能关联。
- 数据范围：角色数据范围及请求边界过滤。
- 租户隔离：租户解析和多租户数据访问边界。

隐藏前端按钮不能替代服务端授权。修改菜单、路由、ModuleCode 或权限字段时，需要同步角色关联、缓存、前端类型和所有消费者。

## 6. SmModule 元数据平台

| 聚合成员 | 职责 |
|---|---|
| `SmModules` | 页面身份、模块代码、名称、路由、API、编辑方式、开关、主从关系、工作流与列表行为 |
| `SmModuleSql` | 主表、字段、连接、条件、排序、分组和查询 SQL 模型 |
| `SmModuleColumn` | 列表列、查询项、表单控件、校验、数据源、显示、排序、导入导出和跳转 |

运行时步骤：

1. 页面以 `moduleCode` 获取 `ModuleInfo`。
2. 后端从模块/栏位缓存和数据库组装 columns、formColumns、actions、menuData、主从信息与用户列偏好。
3. Redux 按模块代码缓存结果。
4. `TableList/ProTable` 和动态表单消费统一契约。
5. 模块、SQL 或栏位修改后刷新相应缓存，前端重新获取配置。

详细约束见[后端 SmModule 专题](../backend/SmModule/README.md)和[前端 SmModule 专题](../frontend/SmModule/README.md)。

## 7. 通用列表与表单

### 通用列表

- 服务端分页、排序、搜索、关键字与自定义条件。
- 动态列、列宽、对齐、固定列、枚举/标签/颜色/图标/链接/图片等渲染。
- 列显示和顺序的用户偏好持久化，以及模块级是否允许定制。
- 新增、查看、修改、删除、自定义行按钮和下拉操作。
- 批量删除、审核、撤销等模块动作。
- Excel 导入/导出、导入预览和结果反馈。
- 日志查看、主从表条件、跨页选择、汇总行和表格内编辑。

### 动态表单

- 新增、编辑、查看和禁用模式。
- Input、TextArea、InputNumber、Password、Select/ComboGrid、Radio、Checkbox、Switch。
- 日期、日期范围、周/月/季度范围、时间与日期时间控件。
- 图片封面、文件上传、颜色选择等扩展控件。
- 必填、唯一、正则、长度、数值范围、占比、标签布局和数据源。
- 主从字段、默认值、创建/修改隐藏与修改只读。

## 8. 工作流与低代码

- `src/workflow/**`：业务流程设计器、开始/审批/条件/通知等节点设置，表单权限和发布。
- `src/workflow-editor/**`：独立编辑器引擎、画布、节点物料、条件分支、撤销重做、缩放、导入导出和校验。
- `views/system/config/form/**`：PC 表单/字段配置与流程入口。
- `views/system/config/mobile/**`：移动页面画布、组件属性、预览、JSON 和保存。
- 后端 `SmWorkFlow*`：流程定义、节点和节点审核持久化及查询。

两套前端流程目录是现存边界，不能仅按名称批量合并或同步。

## 9. 数据与持久化

- 主 ORM：SqlSugar；仓库同时包含 EF Core、Dapper 等访问路径。
- `DataBaseType` 和 SqlSugar 配置入口列出 SQL Server、MySQL、PostgreSQL、Oracle、SQLite、达梦、人大金仓；但当前数据库可用性检查、连接标签和 EF Core Context 只完整处理 SQL Server/MySQL，其他类型必须按具体调用链验证，不能视为端到端已适配。
- `db/**` 保存数据库交付包，`model/**` 保存 PowerDesigner 设计文件。
- 实体公共字段、审计、逻辑删除和索引受[数据库表设计约束](../backend/数据库表设计约束.md)管理。
- 未经授权不得连接、迁移、修复或写入数据库。

## 10. 缓存、事件、任务和日志

- Redis：模块、权限、用户列配置和业务缓存等；需关注 key 范围、租户/用户隔离和刷新时机。
- SignalR：面向用户的实时通信能力，前端依赖 `@microsoft/signalr`。
- Quartz：任务配置、执行和任务日志，由 API 管理、Jobs/Tasks 执行。
- EventBus：使用内存订阅管理器保存订阅关系，并按配置注册 RabbitMQ 或 Kafka 传输；当前目录未发现 Channel/Redis 事件总线实现。
- Serilog：请求、异常、业务、SQL/审计等日志能力，并有 Elasticsearch 扩展项目。

## 11. 文件、导入导出和 AI

- 文件附件：列表、普通上传、图片上传、视频/分片上传、按 URL/ID 获取和下载。
- Excel：动态列表导入导出、模板、预览、错误列和错误记录管理。
- AI：前端 Chat 使用 Ant Design X 组件；主 API 的 Stream 接口将认证上下文委托给 MCP API，并支持分析文件上传。当前 MCP 业务工具仅确认 Supplier 领域。
- 文件和 AI 输入均属于不可信边界，需校验大小、类型、文件名、目标路径、响应格式和认证传播。

具体文件路由、SSE 流程和已发现的匿名入口见[实现链路与源码索引](实现链路与源码索引.md)。

## 12. 构建与部署

- 前端：Vite 构建，支持开发/测试/生产模式、压缩和静态部署；PWA 仅在 `VITE_PWA` 开启时注册，使用自动更新策略。
- 主 API/Jobs/MCP/Gateway：分别构建和部署，不共享宿主生命周期。
- 外部依赖可能包括业务数据库、Redis、RabbitMQ、Nacos、日志存储和 AI/MCP 服务。
- Docker 与服务器环境见 `doc/Docker部署.md`、`doc/初始化服务器.md`、`doc/创建开发环境.md`。
