# EU-Admin 项目说明实现核查报告

> 核查日期：2026-08-09 至 2026-08-10
>
> 核查范围：仓库静态源码与本地参考文档；未连接数据库、Redis、RabbitMQ、Nacos、MCP 服务或任何租户环境。

## 1. 核查方法

本轮不是按目录名称推测功能，而是沿以下证据链反查：

```text
前端 view/moduleCode
  → 通用组件或专用页面中的 API 调用
  → Controller 路由与自定义 Action
  → IService / Service 方法
  → Entity、DTO、Insert/Edit 模型
  → 宿主注册和运行边界
```

静态盘点覆盖：

- React `views` 顶级业务域 13 个，其中业务/系统页面 TSX 包括 basedata 18、purchase 16、sales 13、stock 15、equipment 5、system 55；example 49 个单独标记为示例。
- 主 API Controller 源码目录：BD 20、PO 10、SD 10 个编译内 Controller、IV 9、EM 4、EC 3、SM 52、Tenant 4，并核对 Authorize、Common、Stream、DbFirst 和 Other；SD 另有 `SdOrderController111.cs`，但已被 `EU.Core.Api.csproj` 明确排除编译。
- 四个宿主入口：主 API、Jobs、Gateway、MCP API。

数量用于检查遗漏，不代表每个文件都是独立菜单或已投产功能。

## 2. 已修正或收窄的描述

| 原有概括 | 核查后的准确描述 |
|---|---|
| 当前用户刷新后自动恢复 | token 可持久化；用户详情由 Header 的 `UserName.tsx` 请求 CurrentUser，不是 RouterGuard 主动恢复 |
| 退出会清理全部会话派生状态 | 当前只直接清用户资料、token 和授权菜单；module/tabs Redux 未在 `AvatarIcon` 中清理 |
| 按钮权限来自后端 | 通用模块操作权限来自 `GetModuleInfo`；旧 `usePermissions` 的 `authButtonList` 当前来自本地 JSON |
| MCP 是通用业务平台 | 当前可确认的 MCP Controller/Service 仅 Supplier，主 API 也固定连接 `/Supplier/mcp` |
| 文件接口是 `/api/FileAttachment` | 文件名虽为 `FileAttachmentController.cs`，类名是 `FileController`，默认路由是 `/api/File` |
| 所有库存报表有独立 Controller | 汇总、明细、变动、库龄、预警主要是 moduleCode + Common 动态查询，没有对应独立报表 Controller |
| 工作流是一套编辑器 | `src/workflow/**` 与 `src/workflow-editor/**` 是两套现存前端边界，共享/消费关系不能仅凭名称推断 |
| 动态菜单可从源码还原 URL | 页面组件可确认，但最终路径、ApiUrl 和角色可见性位于数据库模块配置中 |

## 3. 已确认的关键实现事实

- `SmModulesServices.GetModuleInfo` 确实返回 columns、formColumns、actions、动作分组、主从关系、打开方式、API、用户列偏好、操作列位置和自定义列开关。
- 操作按钮超过 3 个时，后端按排序把前 2 个放 `beforeActions`，其余放 `dropActions`。
- 操作列的左右位置和列定制开关已同时被普通 ProTable、EditableProTable 及 Editable 表单表格消费。
- 通用列表查询不是简单实体分页，而是由 ModuleSql/ModuleSqlColumn/GridList 拼装动态 SQL，并支持关键词、排序、角色公司范围和 `[USER_ID]` 占位符。
- 采购、销售的转单/完结和库存的过账均有专用 Controller Action 与 Service，不应描述为普通 CRUD。
- 库存五个查询页面属于动态报表；实现正确性取决于对应 moduleCode 的数据库 SQL 配置。
- Jobs、Gateway、MCP、主 API 是独立进程，依赖和中间件不能互相推定。

## 4. 发现但未修改的实现注意项

这些是静态核查发现但不属于本次 SmModules 字段需求的既有实现注意项，本次未修改：

1. `SmModulesServices.GetModuleInfo` 异常后仍返回 `Success = true`，调用方可能只能从 message 或数据完整性判断失败。
2. `TableList.tsx` 对后端模块配置中的 `FunctionJs` 使用 `eval`，属于高信任配置与前端代码执行边界。
3. `CommonController` 的 GenerateAllEntity、SyncData、InitLanguage、Test 等入口存在 `AllowAnonymous` 标记。
4. `/api/Stream/Upload` 标记 `AllowAnonymous`；流式接口响应写入 `Access-Control-Allow-Origin: *`。
5. `api/modules/mobileConfig.ts` 的列表返回泛型写成数组，而继承的 `QueryByFilter` 返回分页包装，需运行联调确认前端实际解包是否一致。
6. `BaseController` 依赖反射按方法名调用 Service，重命名/重载 Service 方法可能在编译通过后才暴露运行时问题。
7. Controller 文件名与类名不总一致，基于 `[controller]` 的真实路由必须看类名。
8. 退出流程没有直接清理 module/tabs Redux，账号切换需验证旧模块信息和标签页是否残留。
9. `views/purchase/order/index.tsx::PurchaseOrderChange` 调用 `/api/SdOrder/BulkOrderChange`，与采购订单领域不一致。
10. `views/purchase/return/index.tsx::PurchaseNoticeOrderCompleted` 调用 `/api/PoInOrder/BulkOrderComplete`，没有调用后端已存在的 `/api/PoReturnOrder/BulkOrderComplete`。
11. `MonitorController` 整体标记 `AllowAnonymous`，可返回宿主路径、运行环境、访问趋势和活跃用户等信息；是否允许公网访问需要单独安全评审。
12. MCP 的 `create_supplier_from_file` Attribute 描述为解析文件并创建供应商，但当前方法体只返回带固定记录 ID 的前端编辑导航，没有读取 arguments/fileId 或写入供应商。
13. 匿名入口还包括 Server 信息、应用版本/设备记录、导入模板下载、MCP HealthCheck 以及 Values/SplitDemo 等示例 Action；已在系统实现明细中按类别列出。
14. `Authorize/GetAccessToken` 不是普通刷新接口：它匿名查找预设系统管理员并生成 2099 年到期 Token，Service 已标记 Obsolete 且注释明确要求生产禁用。
15. 前端 `layouts/index.tsx` 的 SignalR effect 没有依赖数组或卸载清理，每次渲染可能重复连接、注册监听及 onclose 回调。
16. 首页统计、趋势、表格与占比数据来自页面静态值及 `views/home/config/**`，不能解释为实时经营看板；账号设置页当前只保存用户名和头像，修改密码入口位于 Header 弹窗。
17. `EU.Core.EventBus` 当前实现是内存订阅关系管理加 RabbitMQ/Kafka 传输，并非 Channel/Redis EventBus；`ValuesController.RedisMq` 只是示例入口。
18. `DataBaseType`/SqlSugar 配置虽列出七类数据库，但 `DBHelper` 可用性检查、连接标签及 EF Core Context 只明确处理 SQL Server/MySQL，其他类型不能仅凭枚举声明为完整适配。
19. `src/api/helper/axiosCancel.ts` 存在但没有被请求拦截器或其他生产代码引用，当前不能把“自动取消重复请求”列为已生效能力。
20. `EventBusHostedService` 在启用时解析单个 `IEventBus`；没有开启 RabbitMQ/Kafka 会缺少注册，两者同时开启则单服务解析命中后注册的 Kafka，不能解释为自动同时发布到两套中间件。
21. 主 API 可按配置启用 Nacos Naming/Config 与监听服务，但 Gateway 的 `AddNacosDiscovery()` 当前被注释；存在 Provider 项目不等于网关已经使用 Nacos 服务发现。
22. `Controllers/SD/SdOrderController111.cs` 是被项目文件 `Compile Remove` 的历史实现，不能计入当前 API Controller 或路由能力。
23. Quartz `SchedulerCenterServer` 多处在异步方法中读取 `_scheduler.Result`，并与 `TaskHelper` 一样存在 `AddScheduleJobAsync(...).Result`；任务链路并非完全异步，需关注启动阻塞和异常传播。
24. 主 API 当前无条件执行 `IdentityModelEventSource.ShowPII = true`，开发环境判断代码被注释；生产环境可能输出更详细的身份验证敏感诊断信息。
25. `CorsSetup` 的开放模式接受任意来源，同时允许任意方法、Header 和凭据；是否开启取决于部署配置，生产需要单独安全评审。
26. 匿名 `/api/Stream/Upload` 的 `AnalysisUploadAsync` 只检查 `file is null`，没有限制文件大小、扩展名或 `filePath`，并直接使用请求文件名组合落盘路径，存在路径操纵、任意类型上传和资源耗尽风险。

## 5. SmModules 列表配置字段实现验证

本轮已对 `OptionPosition` 和 `IsAllowCustomColumn` 执行跨端实现核查：

| 验证点 | 已确认行为 |
|---|---|
| 实体与 DTO | `SmModules` 实体和 DTO 基类包含两个字段；操作列位置限制为 `left/right` |
| 新增默认值 | 未提供操作列位置时归一化为 `left`，未提供自定义列开关时归一化为允许 |
| 更新兼容 | 旧客户端未携带新字段时不覆盖数据库原值；显式携带时归一化后更新 |
| 模块复制 | 复制源模块时再次归一化两个字段，并在复制模块、SQL、列配置后刷新三个运行时缓存 |
| API 契约 | `GetModuleInfo` 返回小写 `optionPosition` 和 `isAllowCustomColumn`；旧数据空值按左侧、允许处理 |
| 普通列表 | 操作列按配置前置/后置并固定在相同方向；禁止自定义列时隐藏 setting 入口 |
| Editable 列表 | 两个 EditableProTable 入口以及采购入库、库存入库/出库/盘点/核算的自定义明细列均采用相同左右位置、默认值和开关语义 |
| 重复操作列 | 元数据中已有顶层或嵌套 `option` 列时先移除，再插入唯一的运行时操作列 |
| 模块维护表单 | 动态 `formColumns` 尚未配置两个字段时显示备用 Select/Switch，避免无法维护新配置 |
| 数据库迁移 | 已提供 SQL Server、MySQL 8.0.16+、PostgreSQL 的非幂等迁移、约束和回滚示例；其他数据库需 DBA 适配 |

## 6. 正确性结论

文档现在可确认正确到以下层级：

- 页面文件与仓库中出现的 `moduleCode`：已逐文件提取并核对。
- 标准 CRUD 路由：已对照 `BaseController`。
- 采购、销售、库存、设备的自定义动作：已对照 Controller 与 Service 方法。
- 系统权限、模块设计、工作流、移动页面、导入、附件、AI/MCP：已对照前后端调用点。
- 宿主职责：已对照四个 Program/Startup 入口。

以下内容不能只靠仓库静态源码证明：

- 某环境的最终菜单 URL、菜单层级和角色可见性。
- 数据库内 `SmModules.ApiUrl`、模块 SQL、栏位、功能脚本和用户列配置的实际数据。
- Redis 缓存是否与数据库一致。
- 采购/销售/库存的真实业务数据结果和事务回滚表现。
- 外部数据库、RabbitMQ、MQTT、Nacos、Gateway、MCP/AI 和文件存储是否可用。

因此本文不使用“全部环境已验证”这一表述。静态实现说明已复核；运行时正确性仍需要在隔离环境按真实配置做接口与业务链路验证。
