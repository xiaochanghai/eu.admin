> 状态：`CURRENT`

## 1. 状态与阅读说明

| 状态 | 含义 |
|---|---|
| `CURRENT` | 当前源码中存在前端入口或明确的生产消费链路 |
| `BACKEND-ONLY` | 后端 Controller/Service/模型存在，但当前 React `views` 未发现对应业务页面 |
| `EXAMPLE` | 示例、演示、测试或实验能力，不作为生产菜单承诺 |

动态菜单来自数据库。本文的 `CURRENT` 表示仓库已具备实现，不代表每个部署环境、租户或角色都能看到该菜单。

## 2. 登录、账号与个人能力

| 功能 | 状态 | 用户行为与要点 | 拥有路径 |
|---|---|---|---|
| 账号登录 | `CURRENT` | 输入账号凭据，获取令牌和用户信息；失败通过统一响应提示 | `views/login`、`api/modules/login.ts`、`AuthorizeController` |
| 当前用户恢复 | `CURRENT` | token 可持久化；Header 的 `UserName.tsx` 挂载后调用 CurrentUser 获取用户资料，权限菜单由 `usePermissions` 另行加载 | user/auth Redux、`AuthorizeController.CurrentUser` |
| 开发测试 Token | `EXAMPLE` | `GetAccessToken` 匿名查找预设系统管理员并生成 2099 年到期的 Token；Service 已标记 Obsolete，并明确要求生产禁用 | `AuthorizeController.GetAccessToken`、`SmUsersServices.GetAccessToken` |
| 修改密码 | `CURRENT` | Header 密码弹窗提交旧密码与新密码 | Header `PasswordModal`、`AuthorizeController.RestPassword` |
| 账号设置 | `CURRENT` | 当前页面维护用户名与头像；头像先经 `SmUser/UploadAvatar` 上传，再通过 `PUT /api/SmUser/{UserId}` 保存资料 | `views/account/settings` |
| 退出登录 | `CURRENT` | 调用 LogOut 后清空用户资料、token 和授权菜单并跳转登录；当前 `AvatarIcon` 没有直接清理 module/tabs Redux | Header `AvatarIcon`、user/auth Redux |
| 头像与用户名 | `CURRENT` | Header 展示头像、用户名和用户菜单 | Header `AvatarIcon`、`UserName` |

关键约束：前端会话状态不能替代后端认证；账号切换后不得继续使用旧模块、权限或列表缓存。

## 13. 后台任务、事件、日志与网关

### 13.1 后台任务

- API 侧维护 Quartz 任务和执行日志。
- `EU.Core.Jobs` 作为独立任务宿主启动任务中心。
- `Src/EU.Core.Tasks` 提供 Quartz、Job、触发器及相关执行抽象。
- 后台循环和长任务应支持取消、异常观测和资源释放。

### 13.2 事件总线

- 内存订阅管理器维护事件名称与处理器关系。
- RabbitMQ 与 Kafka 两种事件传输实现，由 `EventBus.Enabled` 及对应中间件开关决定注册。
- 当前 `EU.Core.EventBus` 未发现进程内 Channel 或 Redis 事件总线传输实现；Redis 消息示例不能等同于正式 EventBus Provider。
- 事件处理需考虑至少一次投递、幂等、重试和失败观测。

### 13.3 日志

- Serilog 结构化日志。
- 控制台、文件及可选 Elasticsearch 等输出路径。
- 请求、异常、服务、审计和 SQL 等日志场景。

### 13.4 网关与服务发现

- Ocelot 网关路由。
- 主 Web API 在 `Startup:Nacos:Enabled` 开启时注册 Nacos Naming/Config 客户端与后台监听服务。
- `Ocelot.Provider.Nacos` 项目仍在仓库中，但 Gateway 的 `.AddNacosDiscovery()` 当前被注释，不能把网关侧 Nacos 服务发现标为已启用。
- 网关是独立宿主，不能由 Web API 启动结果替代验证。

- 租户、角色数据范围和 Company/Group 字段不是同一概念。

### 14.2 多数据库

- SqlSugar 为主要多数据库访问能力。
- 同时存在 EF Core、Dapper 和数据库特定 Provider。
- 数据库类型枚举与 SqlSugar 配置入口覆盖 SQL Server、MySQL、PostgreSQL、Oracle、SQLite、达梦、人大金仓等方向；当前数据库可用性探测、连接信息解析和 EF Core Context 仅明确实现 SQL Server/MySQL，其他类型需逐链路验证。
- 公共查询、SQL 和迁移需要考虑方言差异。

### 14.3 DbFirst、CodeFirst 与代码生成

- 数据库表/列读取和备注管理。
- DbFirst 生成实体、DTO、服务、接口和 Controller 等分层文件。
- DynamicCodeFirst 提供动态类型/建表实验接口。
- 独立 `EU.CodeGenerator` 项目拥有生成模板和流程。
- 生成文件带覆盖风险，修改前需确认生成器和手写扩展点。

## 15. AI、MCP 与实时通信

- 前端 AI Chat：欢迎页、提示词、消息气泡、思考内容、Markdown、文件卡片和会话 UI。
- AI Excel/附件上传：将文件作为对话或分析输入。
- 主 API Stream：按 chatId 发起流式请求，将当前认证 Bearer Token 委托给 MCP API。
- MCP API：独立宿主提供模型上下文协议；当前工具仅覆盖 Supplier。列表/新增/更新主要返回前端导航指令，删除会调用 Service；“从文件创建”当前实现只返回带固定 ID 的编辑导航，并未执行工具描述中的文件解析创建。
- SignalR：服务端实时通信与前端连接能力。
- AI/MCP、流式接口和文件响应遵守各自特殊协议，不强行套普通分页/CRUD 响应。

主要路径：`components/Chat/**`、`hooks/useChatUploadExcel.ts`、`StreamController`、`EU.Core.MCP.Api/Services/BD/SupplierService.cs`、SignalR 扩展和测试 Controller。

具体调用链和核查结论见[实现链路与源码索引](实现链路与源码索引.md)与[实现核查报告](实现核查报告.md)。
