# 数据库表设计约束

本文件适用于 `eu.core/**` 中所有新设计或重构的持久化业务表。它是后端表设计的强制事实源；[`../../eu.core/AGENTS.md`](../../eu.core/AGENTS.md) 中的数据库、安全和交付约束同时生效。

## 1. `BaseEntity` 硬约束

- 持久化业务实体必须继承 [`BaseEntity.cs`](../../eu.core/EU.Core.Model/Entity/RootTkey/BaseEntity.cs)，不得在业务实体中复制一套同名公共字段。
- 物理表必须包含 `BaseEntity` 及其基类 [`RootEntityTkey.cs`](../../eu.core/EU.Core.Model/Entity/RootTkey/RootEntityTkey.cs) 定义的全部持久化字段。
- 字段必须保持当前源码定义的类型、可空性、默认值、仅插入/仅更新语义和索引语义；若源码发生变化，应先更新本文件再设计新表。

## 2. 必备字段

| 字段 | 基线约束 |
|---|---|
| `ID` | `Guid`，非空主键，继承自 `RootEntityTkey<Guid>` |
| `IsDeleted` | 逻辑删除标记，默认 `false`，保留索引 |
| `IsActive` | 可空有效标志，默认 `true`，保留索引 |
| `ImportDataId` | 可空 `Guid` |
| `ModificationNum` | 可空整数，默认 `0` |
| `Tag` | 可空整数，默认 `1` |
| `GroupId` | 可空 `Guid`，创建后忽略更新 |
| `CompanyId` | 可空 `Guid`，创建后忽略更新 |
| `AuditStatus` | `varchar(32)`，默认 `Add` |
| `CurrentNode` | `nvarchar(32)`，可空 |
| `CreatedBy` | 可空 `Guid`，仅插入 |
| `CreatedTime` | 可空 `datetime`，仅插入并使用服务端时间 |
| `UpdateBy` | 可空 `Guid`，仅更新 |
| `UpdateTime` | 可空 `datetime`，仅更新并使用服务端时间 |

`ModuleCode` 带有 `SugarColumn(IsIgnore = true)` 和 `NotMapped`，只用于运行时，不得设计为物理表字段。

## 3. 表设计规则

- 表设计评审必须同时核对实体继承、建表 SQL/设计模型、ORM 映射和实际数据库字段，不能只在 SQL 中补字段而让实体绕过 `BaseEntity`。
- `IsDeleted` 和 `IsActive` 必须保留 `BaseEntity` 声明的索引语义；具体索引名称由当前 SqlSugar 规则生成或按目标数据库等价实现。
- `CreatedBy`、`CreatedTime` 不允许在普通更新中覆盖；`UpdateBy`、`UpdateTime` 不参与初始插入语义；`GroupId`、`CompanyId` 创建后不得通过普通更新改变。
- 多租户业务表除公共字段外，还必须按现有租户模式实现相应租户接口并包含隔离字段；不得用 `GroupId` 或 `CompanyId` 替代租户隔离字段。
- 多数据库实现必须保持字段语义一致；数据库方言不同时使用等价类型、默认值和索引，不得静默删除公共字段。

## 4. 变更与例外

- 新增、删除或修改公共字段时，任务附加 `DATABASE` 和 `BACKEND-PLATFORM`，检查全部派生实体、生成器、数据库脚本、ORM 过滤器和前后端消费者。
- 确需偏离该基线时，必须由项目所有者明确批准，并在交付中列出缺失字段、技术原因、ORM/过滤器影响、兼容性和回滚方案。
- 未经明确授权，不连接或写入任何数据库验证表结构；优先使用实体、SQL、模型文件和隔离测试进行静态核对。
