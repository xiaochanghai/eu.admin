## 1. 表结构与完整性

| 检查项 | 结果 |
|---|---:|
| `SmModules` 实际记录数/物理列数 | 243 / 47 |
| `SmModuleSql` 实际记录数/物理列数 | 172 / 35 |
| `SmModuleColumn` 实际记录数/物理列数 | 1991 / 76 |
| 找不到 `SmModules` 的 `SmModuleSql` | 0 |
| 找不到 `SmModules` 的 `SmModuleColumn` | 5 |
| 同一 `ModuleId` 存在多条未删除 `SmModuleSql` | 0 |

- 三张表只有 `ID` 主键以及 `IsActive`、`IsDeleted` 普通索引，没有三表之间的物理外键，也没有约束 `SmModuleSql.ModuleId` 唯一的数据库索引。因此“一个模块至多一条有效 SQL”和“不得产生孤儿栏位”必须由应用层写路径在事务中主动校验。
- 5 条孤儿栏位均为 `IsDeleted=false`、`IsActive=true`：1 条 `SmModuleId` 为空且主要业务字段为空；其余 4 条分别指向两个已不存在的模块 ID，字段为日期、备注和实施进度等历史配置。它们是既有数据问题，未经数据修复授权不得自动处理。
- `information_schema.TABLES.TABLE_ROWS` 对 InnoDB 可能是估算值；上表实际记录数使用 `COUNT(*)`，不得混用两者判断数据增减。

## 2. 示例与现库差异

| 模块 | 用户脚本快照 | 2026-08-07 现库 |
|---|---|---|
| `BD_SUPPLIER_LEVEL_MNG` | 4 条栏位；通用 API | 4 条栏位；模块、查询主体和通用 API 与脚本基本一致 |
| `BD_CUSTOMER_MNG` | 名称“终端客户管理”；`/api/Customer`；14 条栏位；连接 `SmGroup`；部分栏位使用 `ColumnMode=list/form` | 名称“客户管理”；`/api/Common/BD_CUSTOMER_MNG`；25 条栏位；连接地区、客户等级、客户分类、结算方式、送货方式、员工和币别等 7 张表；所有有效栏位的 `ColumnMode` 均为空 |

- 两份 SQL 只用于解释三表聚合和不同配置写法，不得称为当前数据库导出或直接用于覆盖现库。
- 客户管理现库采用 `HideInTable`/`HideInForm` 将名称显示栏位与 ID 表单栏位配对，例如 `DistrictName/DistrictId`、`CurrencyName/CurrencyId`；`ColumnMode=list/form` 是脚本快照展示的另一种配置方式。
- 比较或部署配置时必须以稳定的 `ModuleCode` 定位，再逐项比对主表、SQL、栏位、权限和缓存影响；不能仅凭固定 GUID 或脚本时间判定新旧。
- 如需把样例升级为现库可部署脚本，应从目标库重新导出完整聚合，补事务与环境映射，静态校验每条 INSERT，并在明确授权后于隔离环境验证。
