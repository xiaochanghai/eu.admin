工作流与申请表单设计方案

基于 eu.admin.react 与 eu.core 当前实现整理。本文确定模块开关、字段来源、PC/移动端申请表单和流程条件的职责边界。

最终结论

SmModule.EnableWorkflow 是唯一开关。启用后，模块的流程设置固定包含“流程设计、PC 申请表单、移动端申请表单”；不增加 FormId、EnableFlowForm 或 FlowFormDeviceMode。
SmModule.EnableWorkflow→ 流程设置入口→ 流程设计+ PC 申请表单+ 移动端申请表单

职责边界

对象职责不承担的职责
SmModule模块定义；以 EnableWorkflow 决定是否启用流程设置。不保存字段、表单布局或流程节点。
SmModuleColumn模块的唯一业务字段定义：字段名、标题、控件、数据类型、数据源、必填和校验。不复制为两套 PC/移动端业务字段。
PC / 移动端布局同一字段在不同设备下的排序、隐藏、栅格宽度和分组。不改变字段编码、字段类型或流程条件含义。
SmWorkFlow以 SmModuleId 关联模块，保存已发布的流程节点和审批人规则。不保存申请表单字段副本或 DraftJson/FlowJson。

页面与数据流

  1. 用户进入模块配置。仅当 SmModule.EnableWorkflow = true 时显示“流程设置”入口。
  2. 流程设置页固定展示三个页签：流程设计、PC 申请表单、移动端申请表单。
  3. 两个申请表单页签均通过 /api/SmModule/FormColumn/{moduleId} 读取 SmModuleColumn，字段定义完全一致。
  4. PC 与移动端只保存各自布局。PC 可复用现有 FormTaxisNo、HideInForm、GridSpan 的语义；移动端需要独立的同类布局数据。
  5. 流程条件面板也读取同一批 SmModuleColumn，将字段映射为 FormVo.fields，不再使用 mock 数据。
  6. 点击发布时，保存流程节点、审批人规则和条件 ConditionsJson。不进行实时草稿保存。

布局存储建议

PC 现有字段属性可继续使用。移动端不能覆盖 PC 的排序、隐藏和栅格，因此应增加布局记录，而不是复制 SmModuleColumn。

字段说明
ModuleColumnId关联唯一的 SmModuleColumn。
DeviceType布局记录内部标识，例如 PC 或 Mobile；不是 SmModule 的业务开关。
TaxisNo该设备下的显示顺序。
Hidden该设备下是否隐藏。
GridSpan该设备下的布局宽度；移动端通常为整行。

可以使用独立表 SmModuleColumnLayout，也可以在既有字段配置中增加移动端布局列。字段数量和布局能力会持续增长时，独立表更易维护。

FormDesign 复用方式

现有 src/views/system/config/form/components/FormDesign.tsx 已从 /api/SmModule/FormColumn/{ModuleId} 获取字段，适合复用为流程设置的申请表单设计器。

  • 将组件改为可传入 moduleId 和 layoutType 的嵌入式组件。
  • layoutType = pc 使用 PC 布局读写接口；layoutType = mobile 使用移动端布局读写接口。
  • 字段新增、控件类型、数据源、必填、标题等基础属性仍写入 SmModuleColumn，两个页签共用。
  • 流程设置页负责页签和发布入口；FormDesign 只负责字段和布局编辑，不负责工作流开关判断。

流程条件与发布

  • 条件字段来自 SmModuleColumn，因此无论申请来自 PC 还是移动端，分支判断一致。
  • 条件组之间为“或”，同一条件组内的条件为“且”。
  • 发布校验必须检查：节点完整性、审批人规则、条件字段存在性、运算符与字段类型匹配、路由是否存在兜底分支。
  • 发布接口保存 SmWorkFlowNode、SmWorkFlowNodeAudit 与 SmWorkFlowNode.ConditionsJson；不再使用 DraftJson、FlowJson，也不做进入页面后的实时保存。

当前项目需要补齐的实现

  1. 在 SmModule 和模块配置接口中增加并维护 EnableWorkflow。
  2. 仅在该值为 true 时显示流程设置入口和三个固定页签。
  3. 把当前流程页中由 SmWorkFlow 映射出的空 FormVo.fields 替换为真实 SmModuleColumn 映射。
  4. 将 FormDesign 改造成支持 PC / 移动端布局的可复用组件，并提供移动端布局的后端读写接口。
  5. 删除条件面板的 mock 字段，只允许使用模块真实字段。
现有流程实现是“定义与发布”。若要真正提交申请、创建待办和审批流转，仍需另行实现流程实例、任务和审批日志等运行态能力。
